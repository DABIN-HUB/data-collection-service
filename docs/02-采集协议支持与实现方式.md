# 采集协议支持与实现方式

本页作为协议总索引，优先回答四个问题：

1. 当前哪些协议已经实现。
2. 已实现协议还存在哪些能力边界。
3. 哪些协议只是占位，不能按真实交付承诺。
4. 后续准备补哪些协议，以及它们的方案入口在哪。

判定口径以 `ProtocolDescriptorRegistry`、实际 `ProtocolCollector` 方法和协议测试三者为准。注册表中的
`implemented=true` 只表示已经接入统一采集框架，不等于全部高级能力均已完成。

## 2. 已实现但仍有明确能力边界

| 协议 | 已完成主能力 | 当前边界 |
| --- | --- | --- |
| `BACNET_SC` | 双向 TLS 安全 WebSocket、轮询、分段 APDU、属性写入、COV、会话状态 | 当前状态最多为 `SECURE_TUNNEL_ACTIVE`，标准 Hub/Node BVLL 会话仍未实现 |
| `OMRON_FINS` | FINS/UDP 轮询读写、连续块合并、控制器信息/CPU 状态/时钟命令 | 无原生订阅；RUN/STOP 等高风险命令未开放 |
| `MITSUBISHI_MC` | TCP 轮询读写、3E Binary、3E ASCII、4E Binary | 无原生订阅、UDP、远程 RUN/STOP/RESET，其他帧型未实现 |
| `SIEMENS_S7` | 绝对地址读写、批量计划、驱动支持时订阅 | 无符号浏览/自动导入；数组点位处理规则受限 |
| `ETHERNET_IP` | Logix Tag 读写、批量读写 | 当前连接不支持订阅；数组点位处理规则受限 |
| `ADS` | ADS/AMS 标量及一维同构数组读写、驱动支持时的标量订阅 | 数组订阅暂不开放，需 TwinCAT 实服验证 |
| `KNXNET_IP` | 组地址读写、DPT 映射、驱动支持时订阅 | 实际读写订阅能力受 PLC4X 驱动元数据约束 |
| `OPC_UA` / `OPC_UA_PLC4X` | 标量及一维数组读写、驱动支持时浏览和标量订阅 | 数组订阅暂不开放；浏览和订阅受 PLC4X 驱动元数据约束 |
| `OPC_UA_MILO` | 独立 Milo 连接、读写、浏览和订阅 | 实验性驱动，未替换默认 PLC4X 路由，需双驱动实服契约测试 |
| `MODBUS_RTU` | 寄存器/线圈轮询读写、批量计划 | PLC4X 不提供的诊断命令会明确拒绝，不再返回占位成功 |
| `DLT645_2007` | 2007 帧、串口多表、DI 读取、后续帧、BCD/整数/浮点解析、受控写入 | 实验性；不支持 1997、透明 TCP 和私有 DI 自动识别，需目标电表实测 |
| `IEC101` | 非平衡控制站、FT1.2、一级/二级数据、总召唤、时钟同步、遥控和设点 | 实验性；不支持平衡模式、被控站和文件传输，需目标 RTU 实测 |

`IEC104`、`IEC61850`、`SNMP` 和 `COAP` 的 descriptor 已与实际写入、报告/Trap/Observe 能力对齐。
对于依赖具体连接驱动的能力，接口返回 `RUNTIME_DEPENDENT`，前端必须结合设备运行态判断。

## 3. 已注册但不属于真实可交付协议实现

- [CUSTOM TCP](./protocols/CUSTOM_TCP.md) 与 `CUSTOM_UDP`
  说明：已经拆分为独立 TCP/UDP 适配器，具备固定长度、分隔符、长度字段、UDP 报文边界、受控模板、
  字节/位/JSON 路径解析和请求响应读写能力。由于没有厂商协议样本和实服验收，能力状态保持 `EXPERIMENTAL`，
  不能按特定厂商协议支持对外承诺。

## 4. 计划实现 / 预研协议

- `PROFINET`
- `EtherCAT`

`PROFINET` 和 `EtherCAT` 当前均未注册到 `ProtocolDescriptorRegistry`，不能在控制台中作为 Java 直连协议提供。
工程已增加受 `EDGE_INGEST` 权限保护的 `/api/edge/telemetry` 入口，用于独立实时边缘进程按
`deviceId/pointRef/value/quality/timestamp/sequence` 上送数据；这只是边缘集成骨架，不代表现场总线主站已实现。

## 6. 协议统一入口

- 工厂类：`src/main/java/com/wangbin/collector/core/collector/factory/CollectorFactory.java`
- 抽象接口：`src/main/java/com/wangbin/collector/core/collector/protocol/base/ProtocolCollector.java`
- 通用基类：`src/main/java/com/wangbin/collector/core/collector/protocol/base/BaseCollector.java`
- 连接工厂：`src/main/java/com/wangbin/collector/core/connection/factory/ConnectionFactory.java`
- 协议字段注册：`src/main/java/com/wangbin/collector/core/config/protocol/ProtocolDescriptorRegistry.java`

## 7. 快速说明

- 新增协议时，先实现 `ProtocolCollector`，通常应继承 `BaseCollector`，再在 `ProtocolDescriptorRegistry` 注册 descriptor。
- 若协议需要专用连接管理，则必须在 `ConnectionFactory` 和 `ProtocolConnectionValidator` 一起接入，不允许 collector 自己在框架外单独维护一套连接生命周期。
- 点位差异优先通过 `DataPoint.address + additionalConfig` 承载，不要把协议特性散落到调度、缓存、上报链路。
- 采集结果必须继续走 `BaseCollector` 的 `convertData -> DataQualityProcessor -> ProcessResult` 主链路。
- 推送型数据必须通过 `ingestPushedValue(...)` 进入 `TelemetryIngressService`，保证缓存、上报、Redis Stream、历史存储链路一致。
