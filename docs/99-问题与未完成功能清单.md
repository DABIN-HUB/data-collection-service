# 问题与未完成功能清单

## 1. 协议实现层面

### 1.1 协议码不一致风险（已完成）

- 文件：`common/domain/enums/ProtocolType.java`
- 文件：`core/collector/factory/CollectorFactory.java`

现象：

- 枚举里 SNMP 是 `SNMP_V1/SNMP_V2C/SNMP_V3`，工厂注册是单一 `SNMP`。
- 枚举里有 `MQTT_SSL/COAP_SSL/WEBSOCKET_SSL/HTTPS`，工厂未注册对应键。

风险：

- 平台下发的 `protocolType` 与工厂键不一致会导致无法创建采集器。

完成情况（2026-03-26）：

- 已在 `CollectorFactory` 增加与 `ProtocolType` 对齐的别名映射：`MODBUS_ASCII`、`SNMP_V1/V2C/V3`、`MQTT_SSL`、`COAP_SSL`、`HTTPS`、`WEBSOCKET_SSL`、`CUSTOM_UDP`。
- 已新增测试 `CollectorFactoryProtocolMappingTest`，校验 `ProtocolType` 枚举全部协议码均可被工厂识别。

### 1.2 Custom 协议类型名不一致（已完成）

- 文件：`core/collector/factory/CollectorFactory.java`
- 文件：`core/collector/protocol/custom/CustomProtocolCollector.java`

现象：

- 工厂注册 `CUSTOM_TCP`。
- `CustomProtocolCollector.getProtocolType()` 返回 `CUSTOM_PTL`。

风险：

- 状态展示、日志统计或上层判断可能出现协议名不一致。

完成情况（2026-03-26）：

- `CustomProtocolCollector.getProtocolType()` 和 `getCollectorType()` 已改为基于 `deviceInfo.protocolType` 动态返回，不再固定返回 `CUSTOM_PTL`。
- 未配置设备协议类型时，默认回退为 `CUSTOM_TCP`，保证兼容性。
- 已新增测试 `CustomProtocolCollectorTest`，验证 `CUSTOM_UDP` 场景下返回值与设备协议一致。

### 1.3 HTTP / WebSocket 仍是占位级实现

- 文件：`protocol/http/HttpCollector.java`
- 文件：`protocol/websocket/WebSocketCollector.java`

现象：

- HTTP 的读逻辑返回示例值 `"HTTP Value: ..."`。
- WebSocket 的消息解析函数 `handleWebSocketMessage` 未实现真正解析。

风险：

- 在真实生产环境中会出现“连接成功但数据不真实/不更新”。

### 1.4 OPC DA 当前是内存桥

- 文件：`protocol/opc/OpcDaCollector.java`
- 文件：`protocol/opc/da/InMemoryOpcDaBridge.java`

现象：

- 默认桥接实现为内存模拟，不是现场 OPC DA 驱动。

风险：

- 可用于结构联调，不可直接当真实 OPC DA 采集实现。

### 1.5 SNMPv3 安全参数未完整实现

- 文件：`protocol/snmp/base/AbstractSnmpCollector.java`

现象：

- 代码中明确提示 SNMPv3 安全参数暂未完整实现。

风险：

- 对 SNMPv3 的鉴权/加密能力不完整，需补齐 USM 参数。

## 3. 配置与可维护性问题

### 3.1 Redis Stream 配置前缀

- 文件：`core/cache/config/TelemetryStreamProperties.java`

当前前缀：`spring.data.redis.stream`

说明：

- 目前与 `application.yml` 已匹配（可工作）。
- 若希望业务配置从 `spring.*` 解耦，建议迁移到 `telemetry.stream` 并统一文档。

### 3.2 编码与注释可读性

现象：

- 多个源码文件出现注释/日志中文乱码（历史编码问题）。

影响：

- 增加维护难度，不影响运行但影响长期协作效率。

## 4. 建议优先级

1. 先统一协议码（`ProtocolType` 与 `CollectorFactory` 一致）。
2. 补齐 HTTP/WebSocket/Custom 的真实采集语义。
3. 明确 OPC DA 真实驱动接入方案，替换 InMemory bridge。
4. 完成 storage 与 config/auth/filter 的空实现。
5. 统一源码 UTF-8 编码并清理乱码注释。
