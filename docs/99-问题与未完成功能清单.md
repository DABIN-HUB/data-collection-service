# 问题与未完成功能清单

## 1. 协议实现层面

### 1.1 协议码不一致风险（已完成）

- 文件：`common/domain/enums/ProtocolType.java`
- 文件：`core/collector/factory/CollectorFactory.java`

现象：
- 枚举中的协议码与工厂注册键存在不一致风险（例如 `SNMP_V1/V2C/V3`、`HTTPS`、`WEBSOCKET_SSL` 等）。

完成情况（2026-03-26）：
- 已在 `CollectorFactory` 中补齐 `ProtocolType` 对应别名映射。
- 已新增测试 `CollectorFactoryProtocolMappingTest`，校验枚举协议码均可被工厂识别。

### 1.2 Custom 协议类型名不一致（已完成）

- 文件：`core/collector/factory/CollectorFactory.java`
- 文件：`core/collector/protocol/custom/CustomProtocolCollector.java`

现象：
- 工厂注册为 `CUSTOM_TCP`，但采集器曾固定返回 `CUSTOM_PTL`。

完成情况（2026-03-26）：
- `CustomProtocolCollector.getProtocolType/getCollectorType` 已改为基于设备 `protocolType` 动态返回。
- 未配置时回退 `CUSTOM_TCP`，兼容旧配置。
- 已新增测试 `CustomProtocolCollectorTest`。

### 1.3 HTTP / WebSocket 占位实现（已完成）

- 文件：`protocol/http/HttpCollector.java`
- 文件：`protocol/websocket/WebSocketCollector.java`

完成情况（2026-03-26）：
- `HttpCollector` 已实现 read/batchRead/write/command 的真实请求响应流程与结果映射。
- `WebSocketCollector` 已实现消息解析（`pointId+value`、`values` map、数组结构）与缓存回填。

剩余风险：
- 若上下游报文字段与约定不一致，仍可能出现“有响应但无法映射点位”的联调问题。

### 1.4 OPC DA 内存桥占位（已完成）

- 文件：`protocol/opc/OpcDaCollector.java`
- 文件：`protocol/opc/da/RemoteOpcDaBridge.java`
- 文件：`protocol/opc/da/OpcDaBridgeMode.java`
- 文件：`protocol/opc/da/OpcDaConfig.java`

原问题：
- 默认桥接实现为 `InMemoryOpcDaBridge`，仅用于结构联调，不是生产可用的真实 OPC DA 接入方式。

完成情况（2026-03-26）：
- 已新增 `RemoteOpcDaBridge`，通过 HTTP 调桥接服务实现 OPC DA 读写订阅。
- 已新增 `OpcDaBridgeMode`，支持 `INMEMORY/HTTP` 切换。
- `OpcDaCollector` 已支持通过连接参数动态选择桥接模式；不改动采集器对外生命周期与方法语义。
- `OpcDaConfig` 已扩展桥接参数（`bridgeBaseUrl/token/retry`）。

说明：
- 该改造是“采集服务到 OPC DA 的接入方式替换为 HTTP 桥接”，并非删除 OPC DA 能力。
- 现场 OPC DA 访问职责转移到桥接服务（通常部署在 Windows + COM/DCOM 环境）。

### 1.5 SNMPv3 安全参数治理（已完成）

- 文件：`protocol/snmp/base/AbstractSnmpCollector.java`

完成情况（2026-03-27）：
- 已支持 SNMPv3 USM 用户、安全级别、Auth/Priv 协议与上下文参数。
- `SnmpConnectionAdapter` 注入 USM 用户，`ScopedPDU` 自动带 context。
- 配置项（`snmpSecurityLevel/snmpSecurityName/snmpAuthProtocol/snmpPrivProtocol/...`）及示例详见 [SNMP 协议文档](./protocols/SNMP.md)。

### 1.6 IEC104 / IEC61850 未纳入统一连接管理（已完成）

- 文件：`core/connection/factory/ConnectionFactory.java`

### 2.1 MQTT 下行反控链路（暂未实现）

相关文档：
- [上下行消息协议与实现状态](./11-上下行消息协议与实现状态.md)

现状：
- `MqttReportHandler` 作为统一上报通道，已支持发布属性/事件消息，并支持接收 ACK topic。
- `MqttReportHandler.messageArrived(...)` 对非 ACK 消息仅记录日志，暂未解析 `thing.property.set`、`thing.service.invoke` 等业务下行消息。
- `MqttCollector` 作为 MQTT 采集协议，已能订阅点位 topic 并进入 `ingestPushedValue(...)`，但它不负责把平台下行消息转发给其他协议设备。
- `CollectionManager.writePoint(...)`、`writePoints(...)`、`executeCommand(...)` 已具备统一协议写入/命令入口。

缺口：
- 缺少 MQTT 下行 topic 订阅配置与业务消息解析。
- 缺少 `productKey/deviceName/deviceId + params字段` 到内部设备和点位的路由。
- 缺少 `thing.property.set` 到 `CollectionManager.writePoints(...)` 的调用。
- 缺少 `thing.service.invoke` 到 `CollectionManager.executeCommand(...)` 的调用。
- 缺少执行结果响应消息发布。

影响：
- 目前平台不能通过统一 MQTT 上报连接直接下发属性设置或服务调用到 Modbus、OPC、IEC、SNMP 等协议设备。
