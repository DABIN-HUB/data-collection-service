# IEC104

## 实现类

- `core/collector/protocol/iec/Iec104Collector`
- 基类：`core/collector/protocol/iec/base/AbstractIce104Collector`

## 实现方式

- 基于 `j60870` 建立 IEC104 连接。
- 连接生命周期已纳入 `ConnectionManager` 统一管理：
  - `ConnectionFactory` 按 `IEC104` 创建 `Iec104ConnectionAdapter`
  - 采集器在 `doConnect/doDisconnect` 中通过 `connectionManager.create/connect/remove` 管理连接
  - 采集读写与召唤逻辑仍在 `Iec104Collector` / `AbstractIce104Collector` 中执行
- 支持缓存命中、读失配触发单点召唤。
- 支持总召唤、周期召唤、命令下发。

## 地址与点位配置

- 读取地址格式：`ioa`、`typeId:ioa` 或 `typeName:ioa`。
- 写入地址必须是强类型格式：`typeId:ioa` 或 `typeName:ioa`，不允许只写 `ioa`。
- 读 commonAddress 可来自：点位 `additionalConfig.commonAddress`、点位顶层 `commonAddress`、点位 `unitId`、设备默认。
- 写 commonAddress 优先来自：点位 `additionalConfig.writeCommonAddress`；未配置时回退到读 commonAddress。
- IEC104 TypeId 元数据统一维护在 `Iec104Type` 枚举里，地址解析保留协议真实 TypeId，读缓存匹配时才按类型族归一化。

### 推荐的可读地址写法

- 为了降低配置门槛，IEC104 点位地址更适合支持 `typeName:ioa` 的写法，例如：
  - `M_ME_NC_1:1`
  - `M_SP_NA_1:2001`
- 其中：
  - `typeName` 表示 IEC104 类型标识名称
  - `ioa` 表示信息对象地址
- `commonAddress` 仍建议保持为独立字段，不写入 `address`。
- 因此：
  - `M_ME_NC_1:1` 中的 `1` 是 IOA，不是 commonAddress
  - commonAddress 仍来自连接默认值 `slaveId`，或点位级 `additionalConfig.commonAddress` / `commonAddress` / `unitId`
- 兼容性建议：
  - 保留现有 `ioa` 与 `typeId:ioa` 写法，避免影响已有配置
  - 新配置优先使用 `typeName:ioa`

  - `M_ST_* / M_BO_* / M_IT_* / M_ME_ND_1` 等常见类型名
  - 命令别名，例如 `SINGLE_COMMAND`、`DOUBLE_COMMAND`、`STEP_COMMAND`、`SETPOINT_FLOAT`

## 读写分离配置

IEC104 里同一个业务点经常存在“读取类型”和“写入类型”不一致的情况，例如：

- 遥测读取：`M_ME_NC_1`，typeId = `13`
- 遥调写入：`C_SE_NC_1`，typeId = `50`

因此 RW 点位推荐把读地址和写地址分开配置：

```json
{
  "pointId": "temp_setpoint",
  "pointName": "温度设定",
  "readWrite": "RW",
  "address": "M_ME_NC_1:1",
  "commonAddress": 1,
  "additionalConfig": {
    "writeAddress": "C_SE_NC_1:101",
    "writeCommonAddress": 1,
    "writeSelect": false,
    "writeQl": 0
  }
}
```

字段含义：

- `address`：读取地址，推荐写成 `typeName:ioa`，例如 `M_ME_NC_1:1`。
- `commonAddress`：读取公共地址，仍然独立配置，不写到 `address` 里。
- `additionalConfig.writeAddress`：写入地址，推荐写成写入 ASDU 类型，例如 `C_SE_NC_1:101`。
- `additionalConfig.writeCommonAddress`：写入公共地址；不填时使用 `commonAddress` / `additionalConfig.commonAddress` / `unitId` / 设备默认值。
- `additionalConfig.writeSelect`：写命令 S/E 选择位；`false` 表示执行，`true` 表示选择。当前代码只按该值发送一次命令，不自动补第二次执行。
- `additionalConfig.writeQl`：写命令限定词 QL，默认 `0`。

是否带时标由 `writeAddress` 的 TypeId 决定，不再配置 `writeTimeTag`：

- `C_SE_NC_1:101` / `50:101`：不带时标，发送 `TypeId=50`。
- `C_SE_TC_1:101` / `63:101`：带 CP56Time2a 时标，发送 `TypeId=63`。
- 如果配置中出现 `writeTimeTag`，当前实现会直接报配置错误，避免 `writeAddress` 与时标开关冲突。

解析规则：

- 读取只使用 `address`、读 commonAddress，以及 `typeId` / `iecTypeId` / `registerType`。
- 写入优先使用 `additionalConfig.writeAddress` 和 `additionalConfig.writeCommonAddress`。
- `writeAddress` 只支持 `typeName:ioa`、`typeId:ioa`。
- `writeAddress` 不允许只写 `ioa`，因为无法从 IOA 推断写命令类型和是否带时标。
- 为兼容旧配置，未配置 `writeAddress` 时写入会回退使用 `address`；这种情况下 `address` 必须是写类型，例如 `C_SC_NA_1:10`。
- `writeTypeId` / `writeRegisterType` / `writeType` 不再作为点位写入类型来源；写入类型统一来自 `writeAddress` 或回退后的强类型 `address`。

## 常用扩展参数

- 读取类型：`typeId`、`iecTypeId`、`registerType`
- 写入类型：`writeAddress`、`writeCommonAddress`、`writeQl`、`writeSelect`
- `singleInterrogation*`（由 `collector.iec104` 控制）

## 连接字段整理（createFieldConfig 写法）

说明：
- 当前设备连接字段主要来自 `DeviceConnection`。
- `slaveId` 在 IEC104 中被代码当作默认 `commonAddress` 使用。

```java
fields.add(createFieldConfig("host", "string", "设备IP", true, "127.0.0.1", null));
fields.add(createFieldConfig("port", "number", "端口", true, "2404", null));
fields.add(createFieldConfig("slaveId", "number", "公共地址(commonAddress)", true, "1", null));
fields.add(createFieldConfig("timeout", "number", "协议超时(ms)", true, "5000", null));
```

## 使用方式

1. 设备 `protocolType` 设为 `IEC104`。
2. 配置 `host/port/slaveId(= commonAddress)/timeout`。
3. 点位配置 `address`。
4. 推荐地址格式：
   - 只读点位可写 `ioa`
   - 需要显式表达类型时，推荐写 `typeName:ioa`，例如 `M_ME_NC_1:1`
   - 保留兼容 `typeId:ioa`，例如 `13:1`
5. RW 点位如果读写 ASDU 类型不同，必须在 `additionalConfig.writeAddress` 中明确写类型，例如 `C_SE_NC_1:101`。
6. 纯写点位可以继续把 `address` 写成写类型，例如 `C_SC_NA_1:10`，但新配置仍推荐使用 `writeAddress`。
