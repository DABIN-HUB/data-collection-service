# DL/T 645-2007

## 1. 实现状态

协议代码为 `DLT645_2007`，兼容别名 `DLT645`、`DL_T_645`、`DLT_645_2007`。当前已接入统一采集器、连接工厂、配置校验、协议 Schema、批次策略和采集后处理链，能力状态保持 `EXPERIMENTAL`，完成目标型号电表的连续运行验证后才能调整为 `SUPPORTED`。

当前支持：

- DL/T 645-2007 帧、前导唤醒字节、地址反序、数据域 `0x33` 变换和校验和。
- 读取数据、读取后续数据、读取通信地址。
- BCD、无符号/有符号小端整数、小端浮点、ASCII、日期时间和原始十六进制值。
- 同一串口下多个电表共享物理通道，端口级公平互斥。
- 显式开启并配置密码后的写数据命令。
- 超时、重试、帧间隔和串口参数校验。

当前不支持 DL/T 645-1997、厂商私有 DI 自动识别、广播写、清零等高风险命令，也未实现串口服务器透明 TCP 模式。

## 2. 实现入口

- 采集器：`Dlt645Collector`
- 连接适配器：`Dlt645ConnectionAdapter`
- 帧编解码：`Dlt645FrameCodec`
- 数据编解码：`Dlt645DataCodec`
- 总线请求：`Dlt645Bus`
- 逻辑表计会话：`Dlt645Session`
- 串口共享：`SharedSerialChannelManager`

协议层只返回原始业务值，后续继续由 `BaseCollector` 进入数据转换、质量处理、缓存、Redis、历史存储、告警和上报链路。本地设备身份始终使用 `deviceId`，`meterAddress` 只用于现场总线寻址。

## 3. 连接配置

| 字段 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `serialPort` | 是 | `COM1` | Windows 串口名或操作系统串口设备名 |
| `baudRate` | 是 | `2400` | 波特率 |
| `dataBits` | 是 | `8` | 允许 5 到 8 |
| `stopBits` | 是 | `1` | 允许 1 或 2 |
| `parity` | 是 | `EVEN` | `NONE`、`EVEN`、`ODD` |
| `meterAddress` | 是 | `000000000001` | 12 位十六进制通信地址，按正常阅读顺序填写 |
| `readTimeout` | 否 | `3000` | 单次响应读取超时，单位毫秒 |
| `writeTimeout` | 否 | `3000` | 串口写超时，单位毫秒 |
| `retryCount` | 否 | `2` | 首次请求失败后的重试次数 |
| `wakeupByteCount` | 否 | `4` | 请求前发送的 `0xFE` 数量 |
| `interFrameDelayMs` | 否 | `20` | 写请求后开始读取前的等待时间 |
| `writeEnabled` | 否 | `false` | 是否允许远程写数据 |
| `writePasswordHex` | 写入时是 | 空 | 4 字节十六进制，按协议数据域发送顺序填写 |
| `operatorCodeHex` | 写入时是 | 空 | 4 字节十六进制，按协议数据域发送顺序填写 |

同一个物理串口只能由同一种协议和完全一致的串口参数共享。参数不同或被 IEC101 等其他协议占用时，连接会直接失败，不会并行打开端口造成报文串扰。

## 4. 点位配置

`DataPoint.address` 使用八位十六进制 DI，可写成 `02010100` 或 `DI:02010100`。

点位 `additionalConfig`：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `valueType` | `BCD` | `BCD`、`DECIMAL`、`UINT_LE`、`INT_LE`、`FLOAT_LE`、`ASCII`、`DATETIME`、`HEX` |
| `dataFormat` | 空 | 例如 `XXXXXX.XX`；同时确定单值字节长度和小数位数 |
| `valueIndex` | `0` | 同一 DI 返回多个等长值时，从零开始选取 |

BCD 示例：`dataFormat=XXXXXX.XX` 表示 8 个数字、4 字节、小数点后 2 位。未知或厂商私有 DI 必须按设备手册明确配置，代码不会猜测长度和单位。

## 5. 读写与命令

- 普通采集调用读取数据命令，同一批次内相同 DI 只请求一次。
- 响应控制码声明存在后续帧时，最多继续读取 16 帧，并校验地址、控制码、DI 和序号。
- 写入前必须将 `writeEnabled` 设为 `true`，密码和操作者代码都必须是 8 个十六进制字符。
- 设备命令 `read_address` 用于读取当前总线上的电表通信地址。
- 协议不提供原生订阅；周期采集仍由现有调度器控制。

## 6. 验收

自动化测试覆盖标准帧往返、前导字节、错误校验和、DI 字节序、BCD 编解码和串口引用计数。上线前还必须使用目标电表验证读取、后续帧、异常应答、超时重试、断线恢复和至少 24 小时多表轮询。
