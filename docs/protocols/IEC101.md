# IEC 60870-5-101

## 1. 实现状态

协议代码为 `IEC101`，兼容别名 `IEC_101`、`IEC60870_5_101`。当前实现控制站侧非平衡传输，已接入统一采集、连接、配置、动态 Schema 和遥测后处理链，能力状态为 `EXPERIMENTAL`。

当前支持：

- FT1.2 固定帧、可变帧、单字节确认和校验和。
- 链路复位、链路状态、FCB/FCV、ACD/DFC、确认重传。
- 一级数据、二级数据、总召唤、累计量召唤、读命令和时钟同步。
- 常用遥信、遥测、步位、比特串、累计量、质量描述、CP24 和 CP56 时标。
- 单命令、双命令、调节命令、归一化值、标度值、短浮点和比特串设点命令。
- 选择后执行：先等待选择确认，再发送执行命令。

当前不支持平衡模式、被控站角色、文件传输、参数下载、双机冗余和厂商私有 ASDU。

## 2. 实现入口

- 采集器：`Iec101Collector`
- 连接适配器：`Iec101ConnectionAdapter`
- FT1.2 编解码：`Iec101Ft12Codec`
- ASDU 编解码：`Iec101AsduCodec`
- 链路状态：`Iec101LinkStateMachine`
- 总线请求：`Iec101Bus`
- 站点会话：`Iec101Session`
- 串口共享：`SharedSerialChannelManager`

`deviceId` 是系统设备主键；`linkAddress` 和 `commonAddress` 只参与 IEC101 寻址，不得用于替换缓存、数据库、Redis 或控制台查询使用的设备 ID。

## 3. 连接配置

| 字段 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `serialPort` | 是 | `COM1` | 串口名称 |
| `baudRate` | 是 | `9600` | 波特率 |
| `dataBits` | 是 | `8` | 数据位 |
| `stopBits` | 是 | `1` | 停止位 |
| `parity` | 是 | `EVEN` | `NONE`、`EVEN`、`ODD` |
| `linkMode` | 是 | `UNBALANCED` | 当前只允许非平衡模式 |
| `linkAddress` | 是 | `1` | 链路地址 |
| `commonAddress` | 是 | `1` | ASDU 公共地址 |
| `linkAddressSize` | 是 | `1` | 1 或 2 字节 |
| `causeOfTransmissionSize` | 是 | `2` | 1 或 2 字节 |
| `commonAddressSize` | 是 | `2` | 1 或 2 字节 |
| `informationObjectAddressSize` | 是 | `3` | 1、2 或 3 字节 |
| `readTimeout` | 否 | `3000` | 链路响应超时，单位毫秒 |
| `retryCount` | 否 | `2` | 确认帧未返回时的重试次数 |
| `interFrameDelayMs` | 否 | `20` | 请求发送后的帧间等待 |
| `class1PollIntervalMs` | 否 | `1000` | 订阅状态下一级数据轮询周期 |
| `class2PollIntervalMs` | 否 | `5000` | 订阅状态下二级数据轮询周期 |
| `generalInterrogationOnConnect` | 否 | `true` | 连接完成后执行总召唤 |
| `clockSyncOnConnect` | 否 | `false` | 连接完成后执行时钟同步 |

建立连接时会先发送远方链路复位，再查询链路状态。两步任一失败都不会把设备标记为已连接。

## 4. 点位地址

推荐格式为 `类型名称:IOA`，也允许只填写十进制或 `0x` 前缀的 IOA：

- `M_SP_NA_1:1`：单点遥信，IOA 为 1。
- `M_ME_NC_1:100`：短浮点遥测，IOA 为 100。
- `100`：不限定 TypeId，按公共地址和 IOA 匹配最新样本。

写点位在 `additionalConfig.writeAddress` 中明确命令类型，例如 `C_SC_NA_1:10`。可选字段：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `typeId` | 空 | 兼容的数值类型标识 |
| `writeAddress` | 点位地址 | 命令类型和目标 IOA |
| `writeSelect` | `false` | 是否执行“选择、确认、执行、确认” |
| `writeQualifier` | `0` | 命令限定词；遥控使用低 5 位，设点使用低 7 位 |

## 5. 数据进入系统的方式

- 批量读取优先执行一次总召唤，把样本缓存到“公共地址 + TypeId + IOA”索引。
- 单点缓存缺失时发送读命令，仍缺失时再次总召唤。
- 订阅不是 IEC101 原生推送线程，而是使用系统共享调度器轮询一级/二级数据。
- 轮询得到的事件通过 `TelemetryIngressService.appendRaw(...)` 进入与普通采集一致的数据质量、缓存、历史、告警和上报链路。
- 从站质量位和源时标保留；无效质量不会被伪造成正常值。

## 6. 设备命令

- `general_interrogation`：总召唤，可传 `qualifier`，默认 20。
- `counter_interrogation`：累计量召唤，可传 `qualifier`，默认 5。
- `clock_synchronization` 或 `synchronize_clocks`：发送当前系统时间并等待激活确认。

## 7. 验收

自动化测试覆盖固定帧、可变帧、单字节确认、错误校验和、SQ 地址展开、质量位、命令选择位、限定词和 FCB 翻转。生产启用前必须使用目标 RTU 验证链路复位、一级/二级数据、总召唤终止、遥控否定确认、串口干扰恢复和至少 24 小时连续运行。
