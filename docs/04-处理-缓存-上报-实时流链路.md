# 处理-缓存-上报-实时流链路

## 1. 数据处理链

核心对象：`core/processor/ProcessResult`

在 `BaseCollector.readPoint/readPoints` 中统一完成：

1. 原始值转目标类型（缩放、偏移、布尔/数值转换）。
2. 调用 `DataQualityProcessor` 做质量判定。
3. 产出 `ProcessResult`，并缓存在采集器 `lastProcessResults`。

## 2. 缓存链路

多级缓存核心：

- `MultiLevelCacheManager`
- `LocalCacheManager`
- `RedisCacheManager`

采集结果落缓存入口：

- `core/cache/aspect/CollectorDataCacheAspect`

切面拦截协议采集器读操作后会执行：

1. 写本地/Redis 缓存
2. 调用上报聚合 `CacheReportService.reportPoint(...)`
3. 调用实时流 `TelemetryStreamService.append(...)`

## 3. 上报链路

核心类：`core/report/CacheReportService`

主要机制：

1. 将点位变化聚合进 `ShadowManager`（设备影子）。
2. 只 flush 脏设备（dirty）以降低上报开销。
3. 支持分片、限流、重试、异步上报。
4. 通过 `ReportManager` 分发给 `ReportHandler`（MQTT/HTTP/TCP）。
5. 告警可经 `AlertManager -> CacheReportService.reportAlert(...)` 上报。

## 4. Redis Stream 实时流

核心类：

- `TelemetryStreamProperties`
- `StreamRetentionMode`
- `TelemetryStreamServiceImpl`
- `TelemetryStreamRecordBuilder`

### 4.1 COUNT 模式

- 写入时使用 `XADD MAXLEN` 控制保留条数。
- `approximateTrim=true` 时采用近似裁剪，性能更高。

### 4.2 TIME 模式

- 每条记录带事件时间（`eventTs`）。
- 通过定时任务执行 `XTRIM MINID`，保留最近 N 秒。
- 通过 `trimTaskEnabled`/`trimIntervalMs` 控制定时裁剪。

### 4.3 配置示例

```yaml
spring:
  data:
    redis:
      stream:
        enabled: true
        key: collector:telemetry:stream
        retention-mode: COUNT
        max-length: 200
        max-seconds: 60
        approximate-trim: true
        trim-task-enabled: true
        trim-interval-ms: 5000
```

## 5. 端到端数据时序

1. 调度触发采集。
2. 协议采集器读点位并生成 `ProcessResult`。
3. 缓存切面写缓存。
4. 同步写 Redis Stream（实时消费）。
5. 聚合到影子并按策略上报云端。

## 6. 验证方式

### 6.1 COUNT

1. `retention-mode=COUNT`，`max-length=200`。
2. 连续采集后执行 `XLEN collector:telemetry:stream`。
3. 长时间运行后长度应稳定在 200 左右（近似裁剪可能略浮动）。

### 6.2 TIME

1. `retention-mode=TIME`，`max-seconds=60`，开启 trim 任务。
2. 连续采集 2~3 分钟。
3. 查看流中最早记录时间，窗口应约 60 秒。

### 6.3 兼容性验证

1. 关闭 `spring.data.redis.stream.enabled`。
2. 验证采集、缓存、上报流程仍正常（说明新增功能不破坏主链路）。
