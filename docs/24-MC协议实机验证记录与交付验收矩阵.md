# MC 协议实机验证记录与交付验收矩阵

本文档用于沉淀 `MITSUBISHI_MC` 在 `FX / Q / L / iQ-R` 系列 PLC 上的现场验证记录，并给交付验收提供统一矩阵。

注意：

1. 本文档当前补齐的是 `记录模板 + 验收标准 + 当前代码级证据基线`。
2. 未经真实 PLC 现场联调，不得把 `待填写` 内容改写成“已通过”。
3. 交付结论必须同时参考：
   - 本地自动化测试结果
   - 现场实机验证记录
   - 项目点表实际使用范围

## 1. 当前代码级证据基线

截至 `2026-06-26`，当前版本已具备下列“代码级已验证”证据：

| 能力项 | 证据来源 | 当前结论 | 能否替代实机 |
|---|---|---|---|
| `3E_BINARY` 读写主链路 | `McCollectorIntegrationTest` + `FakeMcServer` | `已覆盖` | `不能` |
| `3E_ASCII` 读写主链路 | `McCollectorIntegrationTest` + `FakeMcServer` | `已覆盖` | `不能` |
| `4E_BINARY` 读写主链路 | `McCollectorIntegrationTest` + `FakeMcServer` | `已覆盖` | `不能` |
| `bit offset` 读写 | `McCollectorTest` + 集成测试 | `已覆盖` | `不能` |
| 稀疏单字标量随机读写 | `McCollectorTest` + 集成测试 | `已覆盖` | `不能` |
| 连续批量写 | `McWritePlanBuilderTest` + 集成测试 | `已覆盖` | `不能` |
| endCode/长度异常/超时/fallback | 单元测试 + 集成测试 | `已覆盖` | `不能` |
| 设备状态诊断字段 | `McCollector` / `MitsubishiMcConnectionAdapter` | `已实现` | `不能` |

当前仍不能由自动化测试替代的事项：

1. `FX / Q / L / iQ-R` 多系列实际兼容性。
2. 不同 CPU、以太网模块、路由参数下的报文兼容性。
3. 长时间运行稳定性、断连恢复、现场网络抖动表现。
4. 项目真实点表下的数据类型、地址类型、批大小和吞吐边界。

## 2. 结论状态定义

现场记录和验收矩阵统一使用下面状态：

| 状态 | 定义 |
|---|---|
| `通过` | 已按要求完成验证，结果满足交付标准 |
| `有条件通过` | 主链路通过，但有明确限制条件，已在验收备注中签字确认 |
| `失败` | 已验证但不满足交付要求 |
| `未验证` | 尚未执行现场验证，不能当作已通过 |
| `范围外` | 当前项目点表和交付范围不涉及 |

## 3. 系列差异重点

现场验证时，不同系列优先关注点不同：

| 系列 | 现场优先确认项 |
|---|---|
| `FX` | 先确认实际 CPU/通信模块是否按项目方案提供 MC/SLMP 能力，再确认帧型、路由参数和点表覆盖 |
| `Q` | 重点确认 `networkNo/pcNo/ioNo/stationNo` 路由参数、旧模块兼容性和批量读写边界 |
| `L` | 重点确认地址覆盖、连续批读批写边界和长时间轮询稳定性 |
| `iQ-R` | 重点确认 `3E_BINARY / 3E_ASCII / 4E_BINARY` 实机表现、较大点表和诊断信息可观测性 |

## 7. 最低交付结论规则

建议按下面规则出交付结论：

1. 所有 `P0` 且“是否阻断交付 = 是”的项，必须为 `通过` 或 `有条件通过`。
2. 任一项目实际使用了 `3E_ASCII / 4E_BINARY / bit offset / random read-write / STRING / FLOAT64`，对应项不得留空。
3. 现场结果为 `有条件通过` 时，必须在备注中写清限制条件，例如：
   - 仅支持 `3E_BINARY`
   - 随机读写仅限单字标量字设备
   - 位内偏移写入存在并发竞争窗口
4. `未验证` 不能出正式“通过验收”结论。

## 9. 建议与当前判断

基于当前代码实现和文档边界，建议统一按下面口径执行交付：

1. `3E_BINARY + 固定点表轮询` 可以作为当前默认交付主路径。
2. `3E_ASCII` 与 `4E_BINARY` 当前是“代码已完成，本地联调已覆盖，实机验收待补齐”。
3. `bit offset` 和稀疏单字标量随机读写已经具备交付前验证价值，但必须写入现场验收记录。
4. 如果目标是“对外通用平台级三菱驱动”，本项目当前仍缺少多系列、多机型、长稳运行的实机证据。
