# 协议实现关系与架构优化记录

本文档记录当前协议实现的上下级关系、连接适配关系、架构优化判断，以及后续针对这些问题的代码修改记录。

## 1. 统一抽象层

采集侧统一入口：

- `ProtocolCollector`：协议采集器接口，定义初始化、连接、读、写、订阅、命令、状态、统计、销毁、读计划重建等能力。
- `BaseCollector`：统一模板基类，负责连接状态、统计、数据转换、质量处理、`ProcessResult` 缓存和异常监控。
- 各协议采集器实现 `BaseCollector` 中的模板方法：
  - `doConnect`
  - `doDisconnect`
  - `doReadPoint`
  - `doReadPoints`
  - `doWritePoint`
  - `doWritePoints`
  - `doSubscribe`
  - `doUnsubscribe`
  - `doGetDeviceStatus`
  - `doExecuteCommand`
  - `buildReadPlans`

连接侧统一入口：

- `ConnectionAdapter<C>`：连接适配器接口。
- `AbstractConnectionAdapter<C>`：统一处理连接状态、重连、心跳、统计和基础发送接收模板。
- `ConnectionManager`：按设备管理连接实例。
- `ConnectionFactory`：按连接类型创建具体适配器。

工厂侧：

- `CollectorFactory`：按 `protocolType` 创建协议采集器。
- `ConnectionFactory`：按 `connectionType` 或 `protocolType` 创建连接适配器。

## 2. 协议实现关系

| 协议 | 采集器继承关系 | 连接/桥接关系 | 实现特点 |
| --- | --- | --- | --- |
| Modbus TCP/RTU | `ModbusTcpCollector` / `ModbusRtuCollector` -> `AbstractModbusCollector` -> `BaseCollector` | `ModbusTcpConnectionAdapter` / `ModbusRtuConnectionAdapter` | 有 `ModbusReadPlan` 聚合读计划；TCP/RTU 读写逻辑相似。 |
| OPC UA | `OpcUaCollector` -> `AbstractOpcUaCollector` -> `BaseCollector` | `OpcUaConnectionAdapter` | 支持读、批量读、写、订阅、browse；订阅回调当前主要记录日志。 |
| OPC DA | `OpcDaCollector` -> `BaseCollector` | `OpcDaBridge` -> `InMemoryOpcDaBridge` / `RemoteOpcDaBridge` | 不走统一 `ConnectionManager`，由采集器内部选择桥接模式。 |
| IEC104 | `Iec104Collector` -> `AbstractIce104Collector` -> `BaseCollector` | `Iec104ConnectionAdapter` | 基于 j60870，支持缓存、读失配单点召唤、总召唤和命令。 |
| IEC61850 | `Iec61850Collector` -> `AbstractIec61850Collector` -> `BaseCollector` | `Iec61850ConnectionAdapter` | 基于 iec61850bean，连接后加载 ServerModel，按模型属性读写。 |
| MQTT | `MqttCollector` -> `BaseCollector` | `MqttConnectionAdapter` | 订阅 topic 后更新 `latestValues`，读取时返回最新值；支持 MQTT v3/v5。 |
| SNMP | `SnmpCollector` -> `AbstractSnmpCollector` -> `BaseCollector` | `SnmpConnectionAdapter` | 支持 GET/SET/WALK；订阅当前主要是点位登记，不是真正 Trap/Inform 流。 |
| CoAP | `CoapCollector` -> `AbstractCoapCollector` -> `BaseCollector` | `CoapConnectionAdapter` | 支持 GET/POST/PUT/DELETE 和 Observe；Observe 回调当前未进入统一后处理链。 |
| HTTP | `HttpCollector` -> `BaseCollector` | `HttpConnectionAdapter` | 请求-响应式读写，支持多种 JSON 响应结构。 |
| WebSocket | `WebSocketCollector` -> `BaseCollector` | `WebSocketConnectionAdapter` | 通过消息队列接收数据，解析后更新 `latestValues`。 |

## 3. 架构优化空间

### 3.1 协议别名与连接工厂映射统一

`CollectorFactory` 支持 `HTTPS`、`MQTT_SSL`、`COAP_SSL`、`WEBSOCKET_SSL`、`SNMP_V1/V2C/V3` 等协议别名，但 `ConnectionFactory` 当前未完整映射这些别名。风险是采集器能创建，但连接适配器创建失败。

建议引入统一协议描述或至少在 `ConnectionFactory` 中进行别名归一化。

### 3.2 抽出连接型采集器基类

多数协议重复执行：

1. 准备连接配置。
2. `connectionManager.createConnection(...)`。
3. `connectionManager.connect(...)`。
4. `instanceof` 校验适配器类型。
5. 失败时静默移除连接。

建议抽出 `ConnectionBackedCollector<A extends ConnectionAdapter<?>>` 或类似基类，减少重复代码并统一失败清理。

### 3.3 拆分胖接口能力模型

`ProtocolCollector` 同时包含读、写、订阅、命令、执行计划等能力，导致不支持某能力的协议也必须实现对应方法。

建议增加能力接口：

- `ReadableCollector`
- `WritableCollector`
- `SubscribableCollector`
- `CommandableCollector`
- `ReadPlanCapable`

调度器和接口层根据能力调用，减少空实现和占位实现。

### 3.4 统一推送型协议的数据入口

MQTT/WebSocket 会更新 `latestValues`，但 OPC UA 订阅和 CoAP Observe 当前主要日志输出，SNMP 订阅也只是登记。推送数据未统一进入 `ProcessResult -> 缓存 -> 上报 -> Redis Stream` 链路。

建议增加统一 `TelemetryIngressService`，让所有订阅/推送回调复用同一后处理链。

### 3.5 收敛 Modbus TCP/RTU 重复逻辑

Modbus TCP 与 RTU 在读计划执行、批量写、解析、异常处理上重复度较高。

建议抽出 `ModbusTransport` 或 `ModbusExecutor`，TCP/RTU 只处理传输差异。

### 3.6 协议批次策略下沉

当前批次上限硬编码在 `DeviceBatchPlanner` 中。新增协议或调整协议策略时，需要修改调度器。

建议由协议描述符或 `ProtocolBatchStrategy` 提供默认批次大小、最大批次大小、地址跨度策略。

### 3.7 统一协议内部异步线程池

部分协议内部使用默认 `CompletableFuture.runAsync`、自建 `ExecutorService` 或自建 `ScheduledExecutorService`，和 `ThreadPoolConfig` 分离。

建议协议内部异步统一注入命名 Executor，便于监控、限流和停机治理。

### 3.8 提升 `BaseCollector.readPoints` 健壮性

`BaseCollector.readPoints` 使用 `parallelStream().collect(toConcurrentMap(...))`，点位失败时 mapper 可能返回 `null`，容易引发集合构造异常。

建议改成显式循环或返回 `ProcessResult.error/skip`，不要用 `null` 表达点位级失败。

### 3.9 修正采集后处理异步边界

`CollectorDataCacheAspect` 中 `@Async` 方法由同类内部调用，Spring AOP 下通常不会真正异步。

建议拆成独立后处理 Bean 或显式注入 Executor。

## 4. 修改记录

### 2026-05-19 修复连接工厂协议别名映射

- 修改 `ConnectionFactory`，增加连接类型别名归一化：
  - `HTTPS` -> `HTTP`，并补齐 `sslEnabled=true`、默认端口 `443`。

  - `MQTT_SSL` -> `MQTT`，并补齐 `sslEnabled=true`、默认端口 `8883`。

  - `SNMP_V1/SNMP_V2C/SNMP_V3` -> `SNMP`，并补齐默认端口和 `snmpVersion`。
  - `MODBUS_ASCII` -> `MODBUS_RTU`。

### 2026-05-19 修复 `BaseCollector.readPoints` 点位级空值处理

- 修改 `BaseCollector.readPoints`：
  - 将原先的 `parallelStream().collect(toConcurrentMap(...))` 改为显式逐点循环。
  - 单个点位原始值为空时，只将该点位结果置为 `null`，不再让整批收集过程异常。
  - 单个点位转换或质量处理异常时，记录异常并将该点位结果置为 `null`，批次继续处理。
- 新增 `BaseCollectorReadPointsTest`，覆盖“批量读中某个点位原始值为空时不抛异常”的场景。
- 已运行验证：
  - `mvn '-Dtest=ConnectionFactoryIecMappingTest,ConnectionFactoryProtocolAliasMappingTest,BaseCollectorReadPointsTest' test`
  - 结果：9 个测试通过，0 失败，0 错误。

### 2026-05-19 修正采集后处理异步边界

- 新增 `CollectorDataPostProcessor` 独立 Bean，承接原切面中的缓存写入、Redis Stream 写入、历史存储写入和上报聚合逻辑。
- 将 `savePointAsync`、`saveBatchAsync` 改为跨 Bean 调用的 public `@Async("cacheAsyncExecutor")` 方法，避免同类内部调用导致 Spring 异步代理不生效。
- 简化 `CollectorDataCacheAspect`，使其只负责从采集结果中提取上下文并委托后处理 Bean 执行。
