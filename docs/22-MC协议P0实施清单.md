# MC 协议 P0 实施清单

本文档用于指导 `MITSUBISHI_MC` 协议在本项目中的第一阶段落地。目标是先做出一个可维护、可扩展、可联调的 P0 版本，而不是一次性把所有 MC 变体全部做完。

## 1. P0 目标

P0 只覆盖下面这条最小可用链路：

1. TCP 连接。
2. MC 3E Binary 帧格式。
3. 轮询读。
4. 基础写入。
5. 点位地址解析。
6. 原始字节到平台值的双向转换。
7. 接入现有调度、缓存、上报链路。

## 2. P0 范围

### 2.1 包含

1. 协议类型：`MITSUBISHI_MC`
2. 传输方式：TCP
3. 报文格式：3E Binary
4. 访问方式：Batch Read / Batch Write
5. 设备地址前缀：
   `M` `X` `Y` `B` `D` `R` `W` `ZR`
6. 地址示例：
   `M0`
   `X1A`
   `Y2F`
   `D100`
   `D100[4]`
   `R200`
   `W300`
   `ZR1000`
7. 支持的数据类型：
   `BOOL`
   `INT16`
   `UINT16`
   `INT32`
   `UINT32`
   `FLOAT32`
   `FLOAT64`
   `STRING`
8. 字符串长度配置：
   `additionalConfig.stringLength`
9. 一维数组长度配置：
   地址自带 `[n]` 或 `additionalConfig.arraySize`

### 2.2 不包含

1. ASCII 帧
2. 4E 帧
3. UDP
4. 订阅
5. 远程 RUN/STOP
6. 随机读写命令
7. 位内偏移写法，例如 `D100.3`
8. 结构体、二维数组、自定义复合类型

## 3. 地址与类型规则

### 3.1 地址规则

1. `X/Y/B/W` 按十六进制地址解析。
2. `M/D/R/ZR` 按十进制地址解析。
3. `BOOL` 只允许位设备：
   `M/X/Y/B`
4. 数值和字符串只允许字设备：
   `D/R/W/ZR`
5. `STRING` 必须提供 `additionalConfig.stringLength`。
6. `STRING` 在 P0 中不支持数组。

### 3.2 点位类型来源

前端和后端统一以 `additionalConfig.driverDataType` 作为 MC 原生类型主字段。

优先级：

1. `additionalConfig.driverDataType`
2. 平台 `dataType` 到 MC 类型映射
3. 位设备在未显式声明时默认按 `BOOL`

## 4. 连接配置字段

P0 连接字段定义如下：

1. `host`
2. `port`
   默认 `5000`
3. `networkNo`
   默认 `0`
4. `pcNo`
   默认 `255`
5. `ioNo`
   默认 `1023`
6. `stationNo`
   默认 `0`
7. `monitoringTimer`
   默认 `16`
8. `readTimeout`
9. `timeout`
10. `maxWordsPerRequest`
    默认 `120`
11. `maxBitsPerRequest`
    默认 `256`

## 6. 开发顺序

### 阶段 A：协议接入框架

1. 注册 `MITSUBISHI_MC` 协议描述器。
2. 定义连接字段、地址提示、原生类型列表。
3. 打通 `CollectorFactory` / `ConnectionFactory` / `ProtocolConnectionValidator` / `DeviceConnection`。

### 阶段 B：地址与类型基础能力

1. 实现地址解析。
2. 实现平台类型到 MC 原生类型映射。
3. 实现字符串长度、数组长度、设备类型校验。

### 阶段 C：通信能力

1. 实现 MC 3E Binary 请求帧构造。
2. 实现响应帧校验与错误码处理。
3. 实现 TCP request-response 连接适配器。

### 阶段 D：采集器

1. 单点读。
2. 批量读。
3. 单点写。
4. 批量写。
5. 设备状态与命令接口。

### 阶段 E：测试

1. 地址解析测试。
2. 字节编解码测试。
3. 帧构造测试。
4. 响应解析测试。
5. 协议 Schema 测试。

## 7. 验收标准

P0 完成时至少满足：

1. 前端可配置 `MITSUBISHI_MC`。
2. 后端能正确校验连接参数。
3. `D100`、`M0`、`X1A` 等地址能被正确解析。
4. 能通过 TCP 发送 3E Binary 批量读写报文。
5. 标量读写可走完整个处理、缓存、上报链路。
6. 错误码、超时、非法地址能返回明确日志与异常。
