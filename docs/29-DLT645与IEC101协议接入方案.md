# DL/T 645-2007 与 IEC 60870-5-101 协议接入方案

## 1. 建设目标

本方案在不改变现有采集调度、数据质量、缓存、Redis、历史存储、告警、上报和 ACK 主链路的前提下，新增以下协议：

1. `DLT645_2007`：面向 DL/T 645-2007 多功能电能表，支持串口多表共享、数据读取、后续帧和受控写入。
2. `IEC101`：面向 IEC 60870-5-101 串行远动设备，实现控制站侧非平衡传输、FT1.2 链路层、ASDU、一级/二级数据、总召唤、时钟同步和受控写命令。

两种协议的本地设备身份始终使用 `deviceId`。电表地址、链路地址和公共地址只是协议寻址字段，不得替换本地设备主键。

## 2. 交付边界

### 2.1 DL/T 645-2007

首版支持：

- 2007 版帧编解码、地址 BCD 编码、数据域 `0x33` 变换和校验和。
- 读取数据、读取后续数据、读取通信地址。
- BCD 数值、整数、浮点、文本、日期时间和原始十六进制解析。
- 同一物理串口下多个电表按地址共享端口并串行执行请求。
- 写数据能力，但必须显式启用并配置密码和操作者代码。
- 串口参数、超时、重试、唤醒字节和帧间隔配置。

首版不声明支持：

- DL/T 645-1997。
- 串口服务器透明 TCP 模式。
- 厂商未公开扩展 DI 的自动语义识别。
- 无密码或无授权条件下的高风险清零、广播和控制操作。

### 2.2 IEC 60870-5-101

首版支持：

- 控制站侧非平衡链路模式。
- FT1.2 固定帧、可变帧和单字节确认。
- 链路复位、链路状态、FCB/FCV、ACD/DFC、一级数据和二级数据轮询。
- 常用遥信、遥测、累计量、质量描述和 CP24/CP56 时标解析。
- 总召唤、读命令、累计量召唤、时钟同步。
- 单命令、双命令、调节命令和设点命令，支持选择/执行配置。
- 多链路地址共享一条串口，按站点公平轮询。

首版不声明支持：

- 平衡链路模式。
- 被控站或服务端角色。
- 文件传输、参数下载、双机冗余和厂商私有 ASDU。

## 3. 公共串口基础设施

新增协议无关的串口通道和共享管理器：

```text
SerialChannel
  -> JSerialCommSerialChannel
  -> InMemorySerialChannel（测试）

SerialEndpoint
  -> 串口号、波特率、数据位、停止位、校验方式

SharedSerialChannelManager
  -> 物理端口唯一打开
  -> 引用计数
  -> 端口级互斥
  -> 配置冲突检测
  -> 最后一个租约释放时关闭端口
```

`jSerialComm` 必须作为直接 Maven 依赖声明，不能继续依赖 `modbus-serial` 的传递依赖。

## 4. DL/T 645-2007 实现结构

```text
core/collector/protocol/dlt645/
  domain/Dlt645Frame
  domain/Dlt645Address
  codec/Dlt645FrameCodec
  codec/Dlt645DataCodec
  transport/Dlt645Bus
  transport/Dlt645Session
  Dlt645Collector

core/connection/adapter/Dlt645ConnectionAdapter
```

点位地址使用 `DI:XXXXXXXX` 或八位十六进制 DI。当前不在代码中固化厂商 DI 语义，点位必须通过 `valueType`、`dataFormat` 和 `valueIndex` 明确解析规则，禁止猜测。

协议读取结果继续返回给 `BaseCollector`，由现有数据转换和质量处理生成 `ProcessResult`。协议异常、校验失败和超时不得写入伪造零值。

## 5. IEC101 实现结构

```text
core/collector/protocol/iec101/
  domain/Iec101Frame
  domain/Iec101Asdu
  domain/Iec101InformationObject
  domain/Iec101Sample
  codec/Iec101Ft12Codec
  codec/Iec101AsduCodec
  link/Iec101LinkStateMachine
  transport/Iec101Bus
  transport/Iec101Session
  Iec101Collector

core/connection/adapter/Iec101ConnectionAdapter
```

IEC101 点位沿用 IEC104 的可读地址习惯：`typeName:ioa`。链路地址和公共地址分别配置，不混入点位地址。

一级、二级和总召唤数据进入协议缓存；点位调度优先读取缓存，缓存缺失时执行读命令或总召唤。后台事件通过统一遥测入口进入质量、告警、缓存、历史和上报链路。

## 6. 注册和配置

两个协议都必须同步接入：

1. `ProtocolDescriptorRegistry`。
2. `CollectorFactory`。
3. `ConnectionFactory`。
4. `ProtocolConnectionValidator`。
5. `ProtocolBatchStrategy`。
6. 前端动态协议 Schema。
7. 协议总览和协议详情文档。

页面字段由后端 Schema 驱动，不在前端新增协议专用硬编码表单。

## 7. 测试和验收

### 7.1 DL/T 645-2007

- 标准帧、前导字节、噪声、拆包、粘包和校验失败。
- 地址反序、`0x33` 变换、BCD 和数据格式解析。
- 异常应答、后续帧、超时重试和响应匹配。
- 同一串口多电表并发和端口引用计数。
- 读取、写入及完整采集后处理链。

### 7.2 IEC101

- 固定帧、可变帧、单字节确认、拆包和校验失败。
- FCB/FCV、ACD/DFC、链路复位、一级/二级轮询和重传。
- 可配置地址长度、SQ 地址展开、质量位和时标。
- 总召唤、读命令、遥控确认和否定确认。
- 多站轮询、断线恢复和完整采集后处理链。

## 8. 实施结果

- 已完成协议描述器、连接工厂、连接参数校验、批次策略和前端动态 Schema 注册。
- 已完成 `jSerialComm` 直接依赖、串口唯一打开、同协议共享、引用计数、端口互斥和冲突检测。
- 已完成 DL/T 645 帧、DI、数据值、后续帧、异常应答、读取和受控写入。
- 已完成 IEC101 FT1.2、ASDU、链路状态、一级/二级数据、召唤、时钟同步、遥控和设点命令。
- 已完成 72 项定向测试，覆盖新增协议和统一注册链路。

当前两个协议均标记为 `EXPERIMENTAL`。真实设备连续运行和故障恢复验证完成后，才能标记为 `SUPPORTED`。
