# MC 协议总览与实施验收手册

本文档合并原：

1. `22-MC协议P0实施清单`
2. `23-MC协议后续实施清单`
3. `24-MC协议实机验证记录与交付验收矩阵`

目标是把 `MITSUBISHI_MC` 的功能范围、当前问题、整改状态、后续计划、实机验证和交付口径放到一份文档里，避免信息分散。

适用对象：

1. 开发人员：看实现范围、边界、问题和后续任务。
2. 实施人员：看现场验证模板、交付验收矩阵和限制条件。
3. 项目经理：看当前能交什么、不能交什么、还差什么。

## 1. 当前结论

截至当前版本，`MITSUBISHI_MC` 已经不是“只有协议骨架”的状态，而是已经具备可联调、可项目化落地的采集主链路。

当前可以明确判断为：

1. `TCP + 3E_BINARY` 已具备常规项目交付能力。
2. `3E_ASCII` 与 `4E_BINARY` 代码已完成并有本地自动化验证，但交付前必须补实机验证。
3. 连续批量读写、`STRING`、`FLOAT64`、位偏移地址、异常断连语义、`reconnect()` 顺序问题都已经有明确实现和测试覆盖。
4. 当前最大的差距已经从“代码没实现”转移到“多系列 PLC 实机兼容验证和现场交付边界”。

更实用的一页判断如下：

| 使用场景 | 核心要求 | 当前判断 | 结论 |
|---|---|---|---|
| 固定点表、常规轮询采集 | `TCP + 3E_BINARY + 批量读写` | 已具备 | `可交付` |
| 现场要求 `3E_ASCII` | `ASCII` 报文兼容 | 代码已具备，缺实机 | `可联调，交付前需实机验证` |
| 现场要求 `4E_BINARY` | `4E` 报文兼容 | 代码已具备，缺实机 | `可联调，交付前需实机验证` |
| 点表包含 `D100.3` 这类字内位偏移 | 位级读写 | 已具备 | `可交付，但仅保证单进程内同字串行` |
| 点位高度离散，希望减少请求数 | `randomRead/randomWrite` | 已具备部分能力 | `仅适合稀疏单字标量字设备点位` |
| 复杂控制类现场 | `RUN/STOP/RESET` 等控制与治理 | 未纳入常规交付 | `不建议承诺` |
| 平台级通用三菱驱动 | 多系列、多机型、长稳实机证据 | 仍不足 | `当前不能按平台级对外承诺` |

## 2. 功能范围与当前边界

### 2.1 已实现能力

| 维度 | 当前状态 | 说明 |
|---|---|---|
| 协议类型 | `MITSUBISHI_MC` | 已注册到统一采集框架 |
| 传输方式 | `TCP` | 已实现连接适配器 |
| 帧型 | `3E_BINARY / 3E_ASCII / 4E_BINARY` | 均有代码和本地测试 |
| 访问方式 | `Batch Read / Batch Write / Random Read / Random Write` | `random` 仅支持部分场景 |
| 地址类型 | `M/X/Y/B/D/R/W/ZR` | 已支持地址解析 |
| 地址扩展 | `D100[4]`、`additionalConfig.arraySize`、`D100.3` | 数组与位偏移均已支持 |
| 数据类型 | `BOOL/INT16/UINT16/INT32/UINT32/FLOAT32/FLOAT64/STRING` | `STRING` 需长度配置 |
| 标量读写 | 已实现 | 单点读写闭环已打通 |
| 批量读写 | 已实现 | 连续地址可做协议级合并 |
| 稀疏随机读写 | 已实现部分 | 仅限稀疏、单字、标量、字设备点位 |
| 位偏移读写 | 已实现 | 写入为 `read-modify-write` |
| 异常断连语义 | 已实现 | 超时、帧头、长度、`4E` 序号异常会强制断连 |
| 连接重连顺序 | 已修复 | `reconnect()` 会先断开旧连接再重连 |
| 调度/缓存/上报接入 | 已实现 | 已接入统一采集框架、缓存和后处理链路 |
| 前端配置 | 已实现 | 控制台已可配置 MC，且已补边界提示 |

### 2.2 当前不纳入默认交付范围

以下能力要么尚未实现，要么不建议作为当前默认交付能力：

1. `UDP` 传输。
2. 原生订阅。
3. 远程 `RUN/STOP/RESET` 等控制类命令。
4. 结构体、二维数组、自定义复合类型。
5. 跨进程、跨系统同时改同一字地址时的全局位级一致性保证。

## 3. 配置、地址与类型规则

### 3.1 连接配置字段

当前连接侧重点字段如下：

| 字段 | 说明 | 默认值/备注 |
|---|---|---|
| `host` | PLC IP | 必填 |
| `port` | 端口 | `5000` |
| `networkNo` | 网络号 | `0` |
| `pcNo` | PC 号 | `255` |
| `ioNo` | IO 号 | `1023` |
| `stationNo` | 站号 | `0` |
| `monitoringTimer` | 监控定时器 | `16` |
| `frameType` | 帧型 | `3E_BINARY / 3E_ASCII / 4E_BINARY` |
| `randomReadEnabled` | 是否启用随机读 | 默认关闭 |
| `maxRandomReadPoints` | 随机读上限 | `8` |
| `randomWriteEnabled` | 是否启用随机写 | 默认关闭 |
| `maxRandomWritePoints` | 随机写上限 | `8` |
| `readTimeout` | 读取超时 | 现场按链路调整 |
| `timeout` | 通用超时 | 现场按链路调整 |
| `maxWordsPerRequest` | 单次字设备请求上限 | `120` |
| `maxBitsPerRequest` | 单次位设备请求上限 | `256` |

### 3.2 点位扩展字段

| 字段 | 说明 | 备注 |
|---|---|---|
| `additionalConfig.driverDataType` | MC 原生类型主字段 | 优先级最高 |
| `additionalConfig.bitIndex` | 位偏移辅助字段 | 当前更推荐直接用 `D100.3` |
| `additionalConfig.stringLength` | 字符串长度 | `STRING` 必填 |
| `additionalConfig.arraySize` | 数组长度 | 地址未显式带 `[n]` 时可用 |

### 3.3 地址规则

1. `X/Y/B/W` 按十六进制地址解析。
2. `M/D/R/ZR` 按十进制地址解析。
3. 位设备默认适配 `BOOL`。
4. `STRING`、数值类型默认适配字设备。
5. `D100[4]` 代表一维数组。
6. `D100.3` 代表字设备中的位偏移地址。

### 3.4 类型规则

类型来源优先级：

1. `additionalConfig.driverDataType`
2. 平台 `dataType` 到 MC 原生类型映射
3. 位设备在未显式声明时默认按 `BOOL`

当前支持的数据类型：

1. `BOOL`
2. `INT16`
3. `UINT16`
4. `INT32`
5. `UINT32`
6. `FLOAT32`
7. `FLOAT64`
8. `STRING`

### 3.5 当前策略边界

1. `randomReadEnabled/randomWriteEnabled` 当前只适用于稀疏、单字、标量、字设备点位。
2. `INT32/UINT32/FLOAT32/FLOAT64/STRING` 当前不走随机读写策略。
3. `STRING` 必须提供 `additionalConfig.stringLength`。
4. `D100.3` 这类位偏移地址只适用于 `BOOL`。
5. 位偏移写入属于 `read-modify-write`。
6. 当前只保证单 collector 进程内同字串行，不保证跨进程一致性。

## 5. 已知问题、风险与整改状态

### 5.1 已完成整改

| 问题/风险 | 当前状态 | 说明 |
|---|---|---|
| 标量 `STRING` 误走通用数值转换 | `已修复` | 现已走 MC 原生编解码与质量处理 |
| 协议异常后连接仍保持“已连接” | `已修复` | 超时、EOF、帧头、长度、`4E` 序号异常均会强制断连 |
| `4E_BINARY` 响应序号未校验 | `已修复` | 已在 codec / parser 层做序号校验 |
| 位偏移写同字并发覆盖 | `已缓解` | 单进程内已按 `deviceId + wordAddress` 串行化 |
| `reconnect()` 先置状态后判连 | `已修复` | 已改为先断旧连接再进入重连 |
| 前端把能力显示成“可配即稳定” | `已修复` | 控制台已补生产边界提示 |

### 5.2 仍需明确告知的限制

以下不是“代码 bug”，但属于必须写清楚的边界：

1. `3E_ASCII` 与 `4E_BINARY` 仍缺多系列 PLC 实机兼容验证。
2. `randomRead/randomWrite` 只支持稀疏单字标量字设备点位。
3. 位偏移写只保证单 collector 进程内不丢位，跨进程仍需要上层治理。
4. 复杂控制类命令不在当前常规采集交付范围内。

### 5.3 不建议并入常规主链路的高风险能力

1. 远程 `RUN/STOP/RESET`。
2. 未经立项单独评审的复杂控制类写入。
3. UDP 传输。
4. 未经实机矩阵验证就默认放开的 `ASCII/4E/random` 全量推广。

## 6. 实施状态与后续任务

### 6.1 已完成项

当前已经完成的核心事项：

1. 协议注册、Schema、地址解析、类型解析、字节编解码。
2. `TCP + 3E_BINARY / 3E_ASCII / 4E_BINARY` 主链路。
3. 单点读写、批量读写、连续地址协议级合并写。
4. 标准调度子批次优先复用预构建读计划。
5. `D100.3` 位偏移地址支持。
6. 稀疏单字标量随机读写。
7. 协议异常后的强制断连。
8. `4E` 序号校验。
9. `reconnect()` 顺序修复。
10. 前端 MC 配置风险边界提示。

### 6.2 后续仍建议推进的 P2 能力

这些能力不是当前阻断项，但仍建议后续推进：

1. 随机读写扩展到多字标量、更广地址组合和字符串场景。
2. 伪订阅模式。
3. 数组语义增强。
4. 更细的多系列 PLC 实机兼容矩阵。

### 6.3 当前最值得继续补的方向

如果继续投入，优先级建议如下：

1. 实机验证矩阵落地并签字。
2. `randomRead/randomWrite` 边界扩展。
3. 更完整的长稳运行与异常恢复现场证据。
4. 交付级验收记录沉淀。

### 7.6 最低交付结论规则

1. 所有 `P0` 且“是否阻断交付 = 是”的项，必须为 `通过` 或 `有条件通过`。
2. 任一项目实际使用了 `3E_ASCII / 4E_BINARY / bit offset / random read-write / STRING / FLOAT64`，对应项不得留空。
3. 现场结果为 `有条件通过` 时，必须在备注中写清限制条件。
4. `未验证` 不能出正式“通过验收”结论。

## 8. 最终交付口径

### 8.1 可交付

以下能力可以作为当前常规项目交付能力：

1. `3E_BINARY + TCP` 常规轮询采集。
2. 连续地址块批量读、批量写。
3. 常规标量类型读写：`INT16/UINT16/INT32/UINT32/FLOAT32/FLOAT64/STRING`。
4. `D100.3` 这类位偏移地址的单进程内读写。
5. 传输异常后的强制断连语义。
6. 通用连接层 `reconnect()` 的正确断连后重连顺序。

### 8.2 需实机验证

以下能力代码已具备，但交付前必须做 PLC 真机联调和回放验证：

1. `3E_ASCII` 全链路。
2. `4E_BINARY` 全链路。
3. `randomRead/randomWrite` 在现场不同 PLC 系列和点表规模下的稳定性。
4. `STRING`、`FLOAT64` 在不同三菱系列 PLC 上的跨机型兼容性。
5. 异常断连后的自动恢复和长时间稳定运行表现。

### 8.3 不建议现场承诺

以下能力当前不建议作为标准交付能力对现场承诺：

1. 多进程、多系统同时改同一字地址时的全局位级一致性。
2. 复杂控制类场景直接复用当前采集链路。
3. 未做实机矩阵验证前，承诺 `ASCII/4E/random` 在所有三菱系列 PLC 上“开箱即稳”。
4. UDP、原生订阅、复杂数组语义增强等未完成或未验收能力。

### 8.4 一句话结论

当前 MC 协议实现已经可以把 `3E_BINARY` 常规采集能力作为交付基线；`ASCII/4E/random` 可以进入联调和试运行，但交付前必须补实机验证；复杂控制类和跨进程同字并发一致性，不建议直接对现场承诺。
