# 配置治理接口说明

## 1. 概述

`ConfigController` 暴露 `/api/config/**` 路由，聚焦于以下场景：

1. 观测：实时查看 ConfigManager 缓存、远端快照、差异及同步状态。
2. 治理：在线更新设备/点位/连接配置并在不影响采集主链路的情况下重新加载。
3. 运维：手动触发指定类型的配置同步、快速导入导出一批设备的配置。

所有接口统一返回结构：

```json
{
  "status": "success | error",
  "message": "描述信息",
  "timestamp": 1774572869000,
  "data": {}
}
```

## 2. 接口速览

| 场景 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 概览 | GET | `/api/config/summary` | 缓存统计、最近/下次同步时间、serviceId。 |
| 查看设备 | GET | `/api/config/devices` | 返回全部设备缓存列表与数量。 |
| 查看单设备 | GET | `/api/config/device/{deviceId}` | 返回本地 + 远端快照及一致性标记。 |
| 点位列表 | GET | `/api/config/device/{deviceId}/points?includeAdaptive=` | `includeAdaptive=true` 时重置自适应采集配置。 |
| 连接配置 | GET | `/api/config/device/{deviceId}/connection` | 查看当前缓存的连接信息。 |
| 差异诊断 | GET | `/api/config/device/{deviceId}/diff` | 比对设备、连接、点位（缺失/多余/内容变化）。 |
| 修改设备 | PUT | `/api/config/device/{deviceId}` | 直接提交 `DeviceInfo` JSON 更新本地缓存。 |
| 修改点位 | PUT | `/api/config/device/{deviceId}/points` | 提交 `List<DataPoint>` 覆盖该设备点位。 |
| 修改连接 | PUT | `/api/config/device/{deviceId}/connection` | 覆盖连接配置，立即更新 DeviceContext。 |
| 刷新设备 | POST | `/api/config/device/{deviceId}/refresh` | 重新加载远端配置（会覆盖本地修改）。 |
| 清空设备缓存 | POST | `/api/config/device/{deviceId}/clear` | 清空 device/point/connection 缓存。 |
| 导出 | GET | `/api/config/export` | 返回 `ConfigBundle` 列表（device + connection + points）。 |
| 导入 | POST | `/api/config/import` | 按 `ConfigImportRequest` 导入一批 bundle，支持导入后触发 reload。 |
| 全量同步 | POST | `/api/config/sync` | 启动异步线程，按配置间隔执行一次 `all` 同步。 |
| 局部同步 | POST | `/api/config/sync/{type}?deviceId=` | `type` ∈ {device, points, connection, collection, all}。 |
| 同步状态 | GET | `/api/config/sync/status` | 返回 lastSyncTime/syncInterval/listenerCount/serviceId。 |

## 4. 导入导出与 reload 行为

- 导出所得 `ConfigBundle` 可直接作为导入模板。
- 导入逻辑：
  1. `device`、`connection`、`points` 任意存在即参与更新，缺省部分保持原样。
  2. 每一步均复用 ConfigManager 的 `update*` 方法，因此自动触发原有 `ConfigUpdateEvent`，不会破坏采集主链路。
  3. `reloadAfterImport=true` 时，会调用 `CollectionService.reloadAllDevices()`，以最新缓存重建采集调度。
- 若需同步远端配置中心（RuoYi），请额外调用 `/api/config/sync/{type}`，注意该操作会覆盖本地修改。

## 5. 错误处理

常见错误及提示：

| 错误场景 | HTTP 码 | message |
| --- | --- | --- |
| 设备不存在/未缓存 | 200 | `设备不存在: {deviceId}`（业务错误，status=error）。 |
| 请求体缺失/格式错误 | 400/500 | Spring 默认错误，由全局异常处理器包装。 |
| 同步类型非法 | 200 | `不支持的同步类型: {type}`。 |
| 导入 bundle 缺少 deviceId | 200 | 结果中的 `failedDevices` 记录 `UNKNOWN`。 |

> 提示：所有接口都属于内网管理面，正式环境请结合 `AuthFilter` + `LogFilter` 落地统一鉴权与访问日志。完成后，可在本接口层引入 token / auditId 等字段补全闭环。
