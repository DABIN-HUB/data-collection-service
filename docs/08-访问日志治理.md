# 访问日志治理实现说明

## 1. 目标

为 `/api/**` 管理接口提供“谁在什么时候做了什么”的可追溯能力，同时对高风险操作（导入、清空、同步）进行显式标记，方便后续与告警、审计联动。由于当前系统尚未引入账号体系，日志以“请求 ID + 来源 IP + Token + 设备 ID”等信号替代用户信息。

## 2. 组件结构

> `AuthFilter`（详见《09-访问鉴权与服务令牌》）已经在请求上写入 `AuthFilter.ATTR_PRINCIPAL`，日志治理可以按需读取该属性，将 serviceId 或调用身份记录到 access log 中，形成完整审计链路。

```
AccessLogProperties (@ConfigurationProperties logging.access.*)
        │
AccessLogConfiguration (自动注入)
        │
LogFilter (OncePerRequestFilter)
```

### 2.1 AccessLogProperties

| 字段 | 说明 | 默认值 |
| --- | --- | --- |
| `enabled` | 是否开启访问日志 | `true` |
| `include-paths` | 需要记录的 Ant 路径 | `/api/**` |
| `exclude-paths` | 忽略路径（心跳、Actuator 等） | `/health`、`/actuator/**` |
| `high-risk-rules` | 高风险方法 + 路径模式 | 见下方示例 |
| `max-query-length` | Query 字符串最大记录长度，超出会截断+“...” | `512` |
| `token-header` | 用于识别调用方的 Token 头 | `X-Collector-Token` |
| `request-id-header` | 请求 ID 头，缺省自动生成 UUID | `X-Request-Id` |
| `additional-headers` | 可选：需要额外透出的 Header | 空 |

### 2.2 LogFilter

核心逻辑：
1. `shouldNotFilter` 依据 include/exclude 判断是否需要记录；支持 `/api/**`、`/health` 等 Ant 样式。
2. `doFilterInternal` 包裹响应，耗时、响应大小等在 finally 中统一写日志。
3. 日志字段（key=value 格式）：
   - `requestId`：优先取 Header，否则生成 UUID。
   - `method`、`uri`、`query`（可配置长度）、`status`、`success`、`latencyMs`。
   - 来源信息：`ip`（`X-Forwarded-For` → `X-Real-IP` → `remoteAddr`）、`token`（来自 Token 头）。
   - 业务信息：`deviceId`（优先 query 参数，其次 `/device/{id}` 路径段）、`reqSize`/`respSize`（可配置）。
   - 额外 header（如 `X-Trace-Id`）可在配置中指定。
4. 高风险命中（method+pattern）后追加 `risk=HIGH`，日志级别提升为 `WARN`，其余情况 `INFO`。
5. 异常兜底：日志写入流程如发生异常，仅打印 warning，不影响主链路。

## 3. 配置示例

`src/main/resources/application.yml` 已内置示例：

```yaml
logging:
  access:
    enabled: true
    include-paths:
      - /api/**
    exclude-paths:
      - /health
      - /actuator/**
    high-risk-rules:
      - method: POST
        pattern: /api/config/import
      - method: POST
        pattern: /api/config/device/**/clear
      - method: POST
        pattern: /api/config/sync/**
    token-header: X-Collector-Token
    request-id-header: X-Request-Id
    max-query-length: 512
```

输出示例：
```
config_access requestId=4d0d0 method=POST uri=/api/config/device/dev-1/clear query=- status=200 success=true latencyMs=35 ip=10.0.0.10 token=ops-token reqSize=128 respSize=64 deviceId=dev-1 risk=HIGH
```

## 4. 扩展点

1. **告警联动**：日志中已有 `risk=HIGH` 标记，可在日志采集中直接配置规则或推送至监控。
2. **审计系统**：若未来需要写入 MQ/ES，可在 `LogFilter` 中追加事件发布，不影响现有结构。
3. **鉴权接入**：当 AuthFilter 落地后，`LogFilter` 可从 `SecurityContext` 中补充 `userId`/`role` 字段。

## 5. 测试

`LogFilterTest` 通过 `MockHttpServletRequest` 验证 include/exclude 逻辑，确保不会错误记录心跳/Actuator 请求，同时 `/api/config/**` 能被纳入治理范围。
