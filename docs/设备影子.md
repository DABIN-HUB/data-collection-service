# 设备影子

## 1. 当前定位

本项目的设备影子位于：

- `core/report/shadow/DeviceShadow`
- `core/report/shadow/ShadowManager`
- `core/report/service/CacheReportService`
- `core/report/downlink/MqttDownlinkService`
- `api/controller/ShadowController`

设备影子现在承担两类职责：

1. 聚合采集结果，维护设备最新 `reported` 状态。
2. 接收 API/MQTT 下行期望值，维护 `desired` 和 `delta`，并驱动协议写入。

影子状态仍以内存为主，已增加 Redis 持久化基础能力。Redis 不可用时不会阻断采集或下行写入主链路。

## 2. 目标模型

设备影子采用如下结构：

```json
{
  "deviceId": "dev-1",
  "version": 12,
  "timestamp": 1710000000000,
  "state": {
    "reported": {
      "temperature": 25.1
    },
    "desired": {
      "temperature": 26.0
    },
    "delta": {
      "temperature": 26.0
    }
  },
  "metadata": {
    "reported": {
      "temperature": {
        "timestamp": 1710000000000,
        "quality": "GOOD"
      }
    },
    "desired": {
      "temperature": {
        "timestamp": 1710000001000,
        "source": "mqtt"
      }
    }
  }
}
```

字段含义：

- `reported`：设备实际已上报状态，来自采集结果。
- `desired`：平台或上层系统期望状态，来自 HTTP API 或 MQTT 下行。
- `delta`：`desired` 中尚未被 `reported` 满足的属性集合。
- `version`：影子状态版本，每次 reported/desired 变化递增。
- `metadata`：属性更新时间、质量、来源等元信息。

## 3. 分阶段计划与状态

### 3.1 本地影子模型

状态：已实现。

已完成：

- `DeviceShadow` 支持 `reported/desired/delta`。
- 保留 dirty、变化触发、事件触发和上报聚合能力。
- 采集结果更新 `reported` 后，如果值等于 `desired`，自动清理对应 desired 字段。
- `ShadowController` 提供查询、写入 desired、清理 desired 接口。

接口：

- `GET /api/shadow/{deviceId}`：查询设备影子完整文档。
- `GET /api/shadow/{deviceId}/delta`：查询待同步差异。
- `POST /api/shadow/{deviceId}/desired`：写入 desired 属性。
- `DELETE /api/shadow/{deviceId}/desired`：清理 desired，可按字段清理。

### 3.2 MQTT 下行反控接入

状态：已实现属性设置和服务调用主链路。

已完成：

- `MqttReportHandler` 对非 ACK 消息接入 `MqttDownlinkService`。
- `ReportConfigProvider` 自动加入默认下行订阅 topic：
  - `/sys/+/+/thing/property/set`
  - `/sys/+/+/thing/service/invoke`
  - `/sys/+/+/thing/config/push`
  - `/sys/+/+/thing/ota/upgrade`
  - `iot/device/+/+/thing/property/set`
  - `iot/device/+/+/thing/service/invoke`
  - `iot/device/+/+/thing/config/push`
  - `iot/device/+/+/thing/ota/upgrade`
- `thing.property.set` 会解析 `params/properties/state.desired`，写入影子 `desired`。
- `thing.property.set` 会按 `reportField/pointAlias/pointCode/pointId/pointName` 匹配 `DataPoint`。
- 匹配到可写点位后调用 `CollectionManager.writePoints(deviceId, Map<DataPoint,Object>)`。
- 执行结果会发布到原下行 topic 加 `_reply` 后缀的响应 topic。

边界：

- 写入成功后不直接伪造 `reported`，仍等待采集回读确认；回读值满足 desired 后自动清理 delta。
- 无法映射或不可写的字段会保留在 desired 中，并在响应里返回字段级错误。

### 3.3 服务调用、配置推送和 OTA

状态：服务调用已接入；配置推送和 OTA 仅识别并返回未实现。

已完成：

- `thing.service.invoke` 会解析 `command/service/identifier/serviceId`。
- 服务调用会路由到 `CollectionManager.executeCommand(deviceId, command, params)`。
- 服务调用执行结果会通过 MQTT 响应返回。
- `thing.config.push` 和 `thing.ota.upgrade` 已能被识别，但返回 `501 not implemented`。

仍未实现：

- `thing.config.push` 接入配置治理链路。
- `thing.ota.upgrade` 的任务模型、下载、校验、安装、回滚、进度上报。

### 3.4 持久化与一致性

状态：已实现基础持久化和本地版本检查；分布式强一致仍未完成。

已完成：

- `ShadowManager` 在 reported/desired/清理/上报窗口变化后，尽力写入 Redis。
- Redis key 格式：`collector:shadow:{deviceId}`。
- 查询影子时，如果本地内存没有，会尝试从 Redis 恢复。
- `POST /api/shadow/{deviceId}/desired` 支持 `shadowVersion` 或 `expectedVersion` 做本地版本冲突检查。
- MQTT `thing.property.set` 同样支持 `shadowVersion` 或 `expectedVersion`。

仍未实现：

- Redis 原子 CAS。
- 多实例并发写入冲突解决。
- 影子过期清理策略。

## 4. 本轮完成情况

本轮完成了剩余主链路中的 MQTT 下行反控和影子持久化基础能力：

- 新增 `MqttDownlinkService` 和 `MqttDownlinkResult`。
- `thing.property.set` 已接入：下行消息 -> desired -> 点位映射 -> 协议写入 -> MQTT 响应。
- `thing.service.invoke` 已接入：下行消息 -> 命令解析 -> `CollectionManager.executeCommand(...)` -> MQTT 响应。
- `MqttReportHandler` 已能把非 ACK 消息转给下行业务服务处理。
- `ReportConfigProvider` 已自动生成 MQTT 下行订阅 topic。
- `ShadowManager` 增加 Redis 持久化、懒加载恢复和本地版本检查。
- `ShadowController` 增加 `shadowVersion/expectedVersion` 版本检查入口。
- 增加 `MqttDownlinkServiceTest`，覆盖属性设置、服务调用、配置推送未实现响应。

验证结果：

- `mvn -DskipTests compile`：通过。
- `mvn '-Dtest=MqttDownlinkServiceTest,ShadowManagerTest,ShadowControllerTest,CacheReportServiceTest' test`：通过，10 个用例成功。

当前仍未完成：

- `thing.config.push` 的实际配置治理执行。
- `thing.ota.upgrade` 的实际 OTA 主流程。
- Redis 原子 CAS、多实例强一致和影子过期清理。
