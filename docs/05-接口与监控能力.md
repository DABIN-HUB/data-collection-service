# 接口与监控能力

## 1. 控制器

### 1.1 设备控制

`api/controller/DeviceController`

- 设备启动/停止/重载
- 设备状态与运行设备查询
- 设备采集统计查询

### 1.2 数据查询

`api/controller/DataController`

- 按设备查点位缓存数据
- 按设备+点位查单点
- 可展开 `ProcessResult` 相关字段
- 历史查询（TDengine启用时）：
  `GET /collector/api/data/history/device/{deviceId}/point/{pointId}`

### 1.3 监控接口

`api/controller/MonitorController`

- 缓存指标
- 设备运行指标
- 性能指标
- 系统资源与异常指标
- 调度详细性能快照

### 1.4 健康与缓存

- `HealthController`：`/health`
- `CacheController`：缓存统计与健康

### 1.5 配置治理

`api/controller/ConfigController`

- `/api/config/summary`：缓存统计 + 最近一次配置同步时间。
- `/api/config/device/*`：查询/更新单设备的设备、点位、连接、差异、刷新、清空。
- `/api/config/export|import`：一键导出/导入设备+点位+连接配置。
- `/api/config/sync*`：触发全局或指定类型/设备的远端配置同步，提供同步状态。
- `/api/config/device/{deviceId}/diff`：返回本地缓存与远端快照的差异清单（设备、连接、点位）。

## 2. 监控实现

### 2.1 健康聚合

`monitor/SystemHealthService`

聚合维度：

- 采集服务健康
- 缓存健康
- 连接健康
- 应用级健康

### 2.2 指标服务

- `CacheMonitorService`
- `DeviceMonitorService`
- `PerformanceMonitorService`
- `ExceptionMonitorService`

## 3. 常用观测建议

1. 采集抖动：看 `PerformanceMonitorService` 的批次耗时和超时趋势。
2. 连接不稳：看连接状态与异常计数是否同步上升。
3. 缓存策略效果：看缓存命中率、Redis 可用性。
4. 上报积压：结合影子脏数据、上报队列与重试次数。

## 4. 管理端联调建议

1. 先通过 `DeviceController` 启动单设备压测。
2. 用 `DataController` 校验点位值与转换结果。
3. 用 `MonitorController` 确认调度和线程池负载是否稳定。
4. 最后验证实时流与上报链路延迟。

## 5. 监控与接口整改计划

详细任务见《16-P0_P1实施任务单与改造方案》的 `API-P1-01` 和 `OPS-P1-01`。

1. 设备状态统一为 `STOPPED/STARTING/RUNNING/DEGRADED/SUSPENDED/FAILED`，禁止用配置态或静态文案代替运行态。
2. 运行态至少包含最后成功采集时间、连续失败、采集延迟、调度代次和退避状态。
3. 线程池统一展示 active、pool、queue、completed 和 rejected；零值必须能区分“当前空闲”和“未接入统计”。
4. 增加配置最后成功同步时间、Outbox 最老消息、ACK 超时、Redis 和 TDengine 状态。
5. 接口统一成功和错误结构，业务错误必须使用正确 HTTP 状态码。
6. 控制台顶部站点、用户和运行状态不得使用容易被误认为真实数据的占位值。
7. 应用启动失败必须返回非零退出码；停机按入口、采集、后处理、Outbox 和连接顺序执行。

监控验收不能只验证接口有返回值，还必须注入停采、队列积压、配置过期和下游故障，确认页面和接口能准确识别。
