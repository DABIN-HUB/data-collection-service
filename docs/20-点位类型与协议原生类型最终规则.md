# 点位类型与协议原生类型最终规则

## 1. 目的

本文件固化点位配置里 `dataType`、`driverDataType`、`pointFields` 以及类型展示模式相关 schema 字段的最终分工。

它约束四件事：

- 后端协议解析与读写优先级
- `ProtocolSchema` 的输出字段
- 前端点位编辑页的主类型展示逻辑
- 后续新增协议时的字段设计方式

相关实现入口：

- `src/main/java/com/wangbin/collector/core/config/protocol/ProtocolSchema.java`
- `src/main/java/com/wangbin/collector/core/config/protocol/ProtocolDescriptorRegistry.java`
- `src/main/resources/static/admin/app.js`
- `src/main/resources/static/admin/local-point-editor.js`

## 2. 总原则

1. 平台层必须保留统一 `dataType`。
2. 驱动层允许有协议原生类型，但不能让每个协议在顶层再扩散出一套新的 datatype 字段。
3. `Modbus` 继续以 `dataType` 作为驱动主类型。
4. 其他协议只有在驱动层确实存在独立原生类型时，才启用 `driverDataType` 或协议专属主类型字段。
5. 前端不能写死协议分支来决定“主类型字段是谁”，必须由 schema 元数据驱动。
6. 现有 `dataTypes` 只增不减，不能为了某个协议去缩减历史类型集合。

## 3. 最终双层模型

| 层级 | 字段 | 作用 | 说明 |
| --- | --- | --- | --- |
| 平台层 | `DataPoint.dataType` | 平台统一类型 | 用于缓存、上报、历史存储、通用值转换、通用页面展示 |
| 驱动层 | `DataPoint.additionalConfig.driverDataType` | 协议原生类型 | 用于驱动解析、取值长度、编码解码、写值 coercion |

例外：

- `MODBUS_TCP` / `MODBUS_RTU`：直接使用 `dataType`
- `KNXNET_IP`：主类型字段不是 `driverDataType`，而是 `additionalConfig.dptId`

## 4. Schema 字段设计表

### 4.1 核心字段

| 字段 | 含义 | 作用 |
| --- | --- | --- |
| `dataTypes` | 平台统一类型候选列表 | 前端 `dataType` 下拉框取这里 |
| `typeMode` | 当前协议采用哪种类型配置模式 | 决定主类型字段是平台类型、驱动原生类型，还是协议专属字段 |
| `primaryTypeField` | 当前协议前端主展示的类型字段路径 | 决定点位详情页“主类型字段”绑定到哪里 |
| `platformDataTypeMode` | 当前协议里 `dataType` 的展示方式 | 决定 `dataType` 是必填、可推导、只读还是放高级区 |
| `driverTypeEnabled` | 是否启用统一的协议原生类型输入区 | 为 `true` 时前端会展示 `driverTypeLabel` 对应的字段 |
| `driverTypeLabel` | 协议原生类型字段中文名 | 例如 `S7 驱动类型`、`SNMP 原生类型` |
| `driverTypeField` | 协议原生类型回写路径 | 当前统一为 `additionalConfig.driverDataType` |
| `driverDataTypes` | 协议原生类型候选列表 | 前端协议原生类型下拉框取这里 |
| `pointFields` | 协议点位扩展字段列表 | 例如 `registerType`、`stringLength`、`dptId`、`nodeId` |

### 4.2 `typeMode` 枚举

| 值 | 含义 | 典型协议 |
| --- | --- | --- |
| `PLATFORM_ONLY` | 只以平台统一 `dataType` 为主 | `MODBUS_*`、`MQTT`、`IEC104` |
| `DRIVER_PRIMARY` | 以协议原生类型为主，`dataType` 仍保留 | `SIEMENS_S7`、`ADS`、`ETHERNET_IP`、`OPC_UA`、`SNMP` |
| `PROTOCOL_FIELD_PRIMARY` | 以协议专属字段为主，不走统一 `driverDataType` | `KNXNET_IP` |

### 4.3 `platformDataTypeMode` 枚举

| 值 | 含义 | 页面行为 |
| --- | --- | --- |
| `REQUIRED` | 必须显式填写 `dataType` | 直接主展示并要求用户明确选择 |
| `DERIVED_EDITABLE` | `dataType` 可根据主类型推导，且允许人工覆盖 | 页面展示 `dataType`，但说明它是平台统一类型 |
| `DERIVED_READONLY` | `dataType` 自动推导，只读展示 | 页面展示但不允许手改 |
| `ADVANCED` | `dataType` 仍保留，但默认不作为主展示字段 | 放高级区或折叠区 |

## 5. 按协议划分的最终规则表

| 协议 | `typeMode` | `primaryTypeField` | `platformDataTypeMode` | 驱动主类型来源 | 备注 |
| --- | --- | --- | --- | --- | --- |
| `MODBUS_TCP` / `MODBUS_RTU` | `PLATFORM_ONLY` | `dataType` | `REQUIRED` | `dataType` | `dataType` 直接决定读取长度、寄存器组合和解码方式 |
| `SIEMENS_S7` | `DRIVER_PRIMARY` | `additionalConfig.driverDataType` | `DERIVED_EDITABLE` | `driverDataType` 优先 | 驱动解析和字符串长度优先参考原生类型 |
| `ADS` | `DRIVER_PRIMARY` | `additionalConfig.driverDataType` | `DERIVED_EDITABLE` | `driverDataType` 优先 | 直接地址、符号地址、数组/字符串长度优先按驱动类型处理 |
| `ETHERNET_IP` | `DRIVER_PRIMARY` | `additionalConfig.driverDataType` | `DERIVED_EDITABLE` | `driverDataType` 优先 | 标签类型和数组处理优先按驱动类型处理 |
| `OPC_UA` / `OPC_UA_PLC4X` | `DRIVER_PRIMARY` | `additionalConfig.driverDataType` | `DERIVED_EDITABLE` | `driverDataType` 优先 | `nodeId`、`namespace`、`identifier` 等继续走 `pointFields` |
| `SNMP` | `DRIVER_PRIMARY` | `additionalConfig.driverDataType` | `DERIVED_EDITABLE` | `driverDataType` 优先 | 允许 `AUTO`，用于 varbind 原生类型适配 |
| `KNXNET_IP` | `PROTOCOL_FIELD_PRIMARY` | `additionalConfig.dptId` | `DERIVED_EDITABLE` | `dptId/dpt` 优先 | KNX 不走统一 `driverDataType` |
| `MQTT` / `IEC104` / `COAP` / `HTTP` / `WEBSOCKET` / `OPC_DA` | `PLATFORM_ONLY` | `dataType` | `REQUIRED` | `dataType` | 协议差异由 `pointFields` 表达 |
| `CUSTOM_TCP` | `PLATFORM_ONLY` | `dataType` | `REQUIRED` | `dataType` | 当前仍为占位实现 |

## 6. 前端渲染规则

### 6.1 主类型字段展示

| `typeMode` | 前端主展示字段 |
| --- | --- |
| `PLATFORM_ONLY` | `dataType` |
| `DRIVER_PRIMARY` | `driverTypeLabel` 对应字段，即 `driverTypeField` |
| `PROTOCOL_FIELD_PRIMARY` | `primaryTypeField` 指向的协议专属字段 |

### 6.2 `dataType` 展示规则

| `platformDataTypeMode` | 页面行为 |
| --- | --- |
| `REQUIRED` | 与主类型字段同级展示，必须填写 |
| `DERIVED_EDITABLE` | 与主类型字段同级展示，但说明它是平台统一类型，可人工覆盖 |
| `DERIVED_READONLY` | 同级展示但禁用编辑 |
| `ADVANCED` | 不作为主展示字段，保留到高级区 |

### 6.3 页面文案要求

1. `driverTypeEnabled`、`driverTypeLabel`、`driverTypeField`、`driverDataTypes`、`pointFields` 出现在前端说明区时，必须有中文含义解释。
2. `Modbus` 页面必须提示：`dataType` 会影响读取长度和寄存器解码。
3. `DRIVER_PRIMARY` 协议必须提示：协议原生类型不会替代平台统一 `dataType`。
4. `PROTOCOL_FIELD_PRIMARY` 协议必须提示：协议专属主类型字段优先决定驱动解析方式。

## 7. 后端取值优先级

### 7.1 驱动层

| 协议组 | 驱动层取值优先级 |
| --- | --- |
| `MODBUS_TCP` / `MODBUS_RTU` | `dataType` |
| `SIEMENS_S7` / `ADS` / `ETHERNET_IP` / `OPC_UA` / `OPC_UA_PLC4X` / `SNMP` | `driverDataType` > 地址中显式类型或兼容字段 > `dataType` > 默认值 |
| `KNXNET_IP` | `dptId` / `dpt` > `dataType` |
| 其他协议 | `pointFields` 协议扩展字段 > `dataType` |

### 7.2 平台层

| 场景 | 平台层取值 |
| --- | --- |
| 缓存 / 上报 / 历史存储 / 通用展示 | `dataType` |
| `dataType` 为空时的兜底 | 可由主类型字段做单向明确映射回填 |
| 映射不明确时 | 不自动猜测，要求显式配置 `dataType` |

## 8. 现阶段实现状态

本轮代码已经落地以下内容：

1. `ProtocolSchema` 新增：
   - `typeMode`
   - `primaryTypeField`
   - `platformDataTypeMode`
2. `ProtocolDescriptorRegistry` 已按协议输出上述三字段。
3. 管理页协议元数据说明区已展示并解释：
   - `typeMode`
   - `primaryTypeField`
   - `platformDataTypeMode`
   - `driverType*`
   - `pointFields`
4. 本地点位编辑器已按 schema 决定主类型字段，不再固定把所有协议都当成“只看 `dataType`”。
5. `SIEMENS_S7`、`ADS`、`ETHERNET_IP`、`OPC_UA`、`SNMP` 的地址解析已优先兼容 `additionalConfig.driverDataType`。

## 9. 新增协议时的执行要求

新增协议前，必须先回答：

1. 该协议是否存在独立于平台 `dataType` 的驱动原生类型？
2. 如果存在，应该走统一 `driverDataType`，还是像 KNX 一样走协议专属字段？
3. 平台 `dataType` 与主类型字段之间是否存在明确映射？
4. 哪些字段应该进 `pointFields`，哪些字段不应冒充成类型字段？

这四个问题没回答清楚，不允许直接再往前端加一个新的 datatype 概念。
