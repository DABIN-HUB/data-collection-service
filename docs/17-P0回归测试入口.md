# P0 回归测试入口

## 1. 目标

固定当前 P0 改造后的最小回归入口，避免每次手工拼接 `-Dtest=...` 参数。

## 2. 固定 Suite

测试套件：

- `src/test/java/com/wangbin/collector/regression/P0RegressionSuite.java`

当前纳入的测试类：

1. `CollectorDataPostProcessorTest`
2. `CollectionSchedulerTest`
3. `CacheReportServiceTest`
4. `TelemetryStreamServiceImplTest`
5. `ShadowManagerTest`

## 3. 固定执行方式

Maven profile：

- `p0-regression`

执行命令：

```bash
mvn -q -Pp0-regression test
```

## 4. 维护规则

1. 新增 P0 定向测试后，同步加入 `P0RegressionSuite`。
2. 如果某个测试上升为主链路关键回归，优先纳入该 suite，而不是继续堆叠命令行 `-Dtest`。
3. 默认 `mvn test` 保持全量测试行为，`p0-regression` 只负责固定的 P0 回归入口。

## 5. 2026-07-14 新增 P0 回归计划

完成《16-P0_P1实施任务单与改造方案》第 9 章任务时，Suite 至少新增以下场景：

1. 配置中心超时和非法响应时保留最后有效快照。
2. 远端明确空快照时才执行设备删除。
3. 单设备超时后下一周期继续执行。
4. 慢设备不影响同时间片其他设备。
5. 服务重启后 dirty 影子和 Outbox 可恢复。
6. ACK 丢失、重复和乱序按消息 ID 与版本幂等。
7. 伪造代理头、篡改请求体和 nonce 重放均被拒绝。
8. P0 回归必须同时验证协议采集数量、点位值、质量和请求次数未发生非预期变化。

新测试落地前本节表示计划，不得将对应 P0 风险标记为完成。
