# 设备影子

## 1. 当前定位

本项目的设备影子位于：

- `core/report/shadow/DeviceShadow`
- `core/report/shadow/ShadowManager`
- `core/report/service/CacheReportService`
- `core/report/downlink/MqttDownlinkService`
- `api/controller/ShadowController`

设备影子现在承担两类职责：

1. 聚合采集结果，维护设备最新 `reported` 状态。
2. 接收 API/MQTT 下行期望值，维护 `desired` 和 `delta`，并驱动协议写入。

影子状态以内存聚合为主，Redis 作为跨实例共享状态和恢复介质。当前已增加 Redis 原子 CAS、TTL 过期、冲突自动合并重试和历史审计：采集 reported 持久化仍按 best-effort 处理，不阻断采集；平台下发 desired 和清理 desired 在 CAS 开启时会以 Redis 当前版本为准，未显式携带版本的写入会在冲突后自动合并重试，显式携带 `expectedVersion/shadowVersion` 的写入仍保持严格乐观锁。

## 2. 目标模型

设备影子采用如下结构：

```json
{
  "deviceId": "dev-1",
  "version": 12,
  "timestamp": 1710000000000,
  "state": {
    "reported": {
      "temperature": 25.1
    },
    "desired": {
      "temperature": 26.0
    },
    "delta": {
      "temperature": 26.0
    }
  },
  "metadata": {
    "reported": {
      "temperature": {
        "timestamp": 1710000000000,
        "quality": "GOOD"
      }
    },
    "desired": {
      "temperature": {
        "timestamp": 1710000001000,
        "source": "mqtt"
      }
    }
  }
}
```

字段含义：

- `reported`：设备实际已上报状态，来自采集结果。
- `desired`：平台或上层系统期望状态，来自 HTTP API 或 MQTT 下行。
- `delta`：`desired` 中尚未被 `reported` 满足的属性集合。
- `version`：影子状态版本，每次 reported/desired 变化递增。
- `metadata`：属性更新时间、质量、来源等元信息。

## 3. 分阶段计划与状态

### 3.1 本地影子模型

状态：已实现。

已完成：

- `DeviceShadow` 支持 `reported/desired/delta`。
- 保留 dirty、变化触发、事件触发和上报聚合能力。
- 采集结果更新 `reported` 后，如果值等于 `desired`，自动清理对应 desired 字段。
- `ShadowController` 提供查询、写入 desired、清理 desired 接口。

接口：

- `GET /api/shadow/{deviceId}`：查询设备影子完整文档。
- `GET /api/shadow/{deviceId}/delta`：查询待同步差异。
- `POST /api/shadow/{deviceId}/desired`：写入 desired 属性。
- `DELETE /api/shadow/{deviceId}/desired`：清理 desired，可按字段清理。

### 3.2 MQTT 下行反控接入

状态：已实现属性设置和服务调用主链路。

已完成：

- `MqttReportHandler` 对非 ACK 消息接入 `MqttDownlinkService`。
- `ReportConfigProvider` 自动加入默认下行订阅 topic：
  - `/sys/+/+/thing/property/set`
  - `/sys/+/+/thing/service/invoke`
  - `/sys/+/+/thing/config/push`
  - `/sys/+/+/thing/ota/upgrade`
  - `iot/device/+/+/thing/property/set`
  - `iot/device/+/+/thing/service/invoke`
  - `iot/device/+/+/thing/config/push`
  - `iot/device/+/+/thing/ota/upgrade`
- `thing.property.set` 会解析 `params/properties/state.desired`，写入影子 `desired`。
- `thing.property.set` 会按 `reportField/pointAlias/pointCode/pointId/pointName` 匹配 `DataPoint`。
- 匹配到可写点位后调用 `CollectionManager.writePoints(deviceId, Map<DataPoint,Object>)`。
- 执行结果会发布到原下行 topic 加 `_reply` 后缀的响应 topic。

边界：

- 写入成功后不直接伪造 `reported`，仍等待采集回读确认；回读值满足 desired 后自动清理 delta。
- 无法映射或不可写的字段会保留在 desired 中，并在响应里返回字段级错误。

### 3.3 服务调用、配置推送和 OTA

状态：服务调用已接入；配置推送和 OTA 仅识别并返回未实现。

已完成：

- `thing.service.invoke` 会解析 `command/service/identifier/serviceId`。
- 服务调用会路由到 `CollectionManager.executeCommand(deviceId, command, params)`。
- 服务调用执行结果会通过 MQTT 响应返回。
- `thing.config.push` 和 `thing.ota.upgrade` 已能被识别，但返回 `501 not implemented`。

仍未实现：

- `thing.config.push` 接入配置治理链路。
- `thing.ota.upgrade` 的任务模型、下载、校验、安装、回滚、进度上报。

### 3.4 持久化与一致性

状态：已实现 Redis 持久化、原子 CAS、多实例冲突自动合并重试、TTL 过期清理和历史版本审计。

已完成：

- `ShadowManager` 在 reported/desired/清理/上报窗口变化后，尽力写入 Redis。
- Redis key 默认格式：`collector:shadow:{deviceId}`，可通过 `collector.report.shadow.key-prefix` 调整。
- 查询影子时，如果本地内存没有，会尝试从 Redis 恢复。
- `POST /api/shadow/{deviceId}/desired` 支持 `shadowVersion` 或 `expectedVersion` 做本地版本冲突检查。
- MQTT `thing.property.set` 同样支持 `shadowVersion` 或 `expectedVersion`。
- desired 写入和 desired 清理已通过 Redis Lua CAS 执行，脚本内完成读取当前影子版本、比较期望版本、写入新 JSON 文档和设置 TTL。
- 多实例并发写入时，如果 Redis 当前 `version` 与本实例写入基线不一致，且请求未显式携带 `expectedVersion/shadowVersion`，会重新加载 Redis 最新影子、合并本次 desired/clear 操作并重试。
- 显式携带 `expectedVersion/shadowVersion` 的写入继续保持严格乐观锁；版本不匹配时抛出 `shadow version conflict`，HTTP 接口返回参数错误，MQTT 下行返回 `409`。
- CAS 失败后会从 Redis 重新加载本地影子，避免本实例继续持有失败写入后的脏内存状态。
- 影子 Redis 数据支持 TTL 过期清理，默认 `collector.report.shadow.ttl-seconds=86400`，小于等于 0 表示不过期。
- 影子持久化支持 `collector.report.shadow.persistence-enabled` 开关，CAS 支持 `collector.report.shadow.cas-enabled` 开关。
- 自动合并支持 `collector.report.shadow.auto-merge-enabled` 开关和 `collector.report.shadow.merge-retry-times` 重试次数配置，默认开启并重试 2 次。
- desired 写入和 clear desired 成功后会写入 Redis list 历史审计，默认 key：`collector:shadow:history:{deviceId}`。
- 历史审计记录包含 `deviceId/action/baseVersion/version/timestamp/document`，默认每设备保留 100 条，TTL 7 天。
- `GET /api/shadow/{deviceId}/history?limit=20` 可查询最近影子审计记录。

仍未实现：

- reported 高频采集变更未写入影子历史审计；这部分仍建议使用 Redis Stream 或 TDengine 历史存储。
- 历史审计目前保存在 Redis list，尚未落到长期审计库。

## 4. 本轮完成情况

本轮完成了 MQTT 下行反控、影子持久化基础能力、Redis 原子 CAS/TTL 过期清理，以及冲突自动合并重试和历史审计：

- 新增 `MqttDownlinkService` 和 `MqttDownlinkResult`。
- `thing.property.set` 已接入：下行消息 -> desired -> 点位映射 -> 协议写入 -> MQTT 响应。
- `thing.service.invoke` 已接入：下行消息 -> 命令解析 -> `CollectionManager.executeCommand(...)` -> MQTT 响应。
- `MqttReportHandler` 已能把非 ACK 消息转给下行业务服务处理。
- `ReportConfigProvider` 已自动生成 MQTT 下行订阅 topic。
- `ShadowManager` 增加 Redis 持久化、懒加载恢复和本地版本检查。
- `ShadowManager` 增加 Redis Lua CAS：desired 写入和 desired 清理会比较 Redis 当前 `version` 后再写入，避免多实例并发覆盖。
- 不带 `expectedVersion/shadowVersion` 的 CAS 写入冲突会重新加载 Redis 中的影子状态，合并本次 desired/clear 操作并按配置重试。
- 带 `expectedVersion/shadowVersion` 的写入继续严格拒绝版本不一致，避免绕过调用方显式乐观锁。
- CAS 写入失败后会重新加载 Redis 中的影子状态，避免本地继续保留未提交成功的 desired。
- 普通 reported 持久化增加 TTL，默认 24 小时后由 Redis 自动清理；可通过 `collector.report.shadow.ttl-seconds` 调整。
- desired 写入和 desired 清理成功后会写入 Redis 历史审计，审计记录保存操作类型、基线版本、新版本、时间和完整影子文档。
- 新增历史查询接口 `GET /api/shadow/{deviceId}/history?limit=20`。
- 新增 `collector.report.shadow.persistence-enabled`、`collector.report.shadow.cas-enabled`、`collector.report.shadow.key-prefix`、`collector.report.shadow.ttl-seconds`、`collector.report.shadow.auto-merge-enabled`、`collector.report.shadow.merge-retry-times`、`collector.report.shadow.history-enabled`、`collector.report.shadow.history-key-prefix`、`collector.report.shadow.history-max-records`、`collector.report.shadow.history-ttl-seconds` 配置项。
- `ShadowController` 增加 `shadowVersion/expectedVersion` 版本检查入口。
- 增加 `MqttDownlinkServiceTest`，覆盖属性设置、服务调用、配置推送未实现响应。
- 增加 `ShadowManagerTest` 覆盖本地版本冲突、Redis CAS 远端版本冲突、TTL 写入、自动合并重试和历史审计写入。

验证结果：

- `mvn -DskipTests compile`：通过。
- `mvn '-Dtest=MqttDownlinkServiceTest,ShadowManagerTest,ShadowControllerTest,CacheReportServiceTest' test`：通过，15 个用例成功。

当前仍未完成：

- `thing.config.push` 的实际配置治理执行。
- `thing.ota.upgrade` 的实际 OTA 主流程。
- reported 高频采集变更进入长期影子审计库。
